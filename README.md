# RiftCast · 英雄联盟赛事导播工作台

当前版本为 **0.4.1（2026-10-07）**，源码仓库为 [QShin21/lolob](https://github.com/QShin21/lolob)。本版新增浅色风格，在「连接与输出 → 外观」切换深色或浅色，立即生效并在当前浏览器或桌面客户端保存。主题覆盖工作台、设置、管理和协作界面，节目输出继续使用 ARENA 播出配色。使用方式与验证范围见 [0.4.1 外观主题说明](docs/外观主题-0.4.1.md)。工作台布局见 [0.4.0 前端改进与验收](docs/前端改进落地-0.4.0.md)，完整操作链路见 [0.3.0 全流程说明](docs/OB全流程改进落地-0.3.0.md)。当前自动检查见 [验收说明](docs/验收.md)。

仓库保留当前源码、`package-lock.json`、启动入口、必要脚本和 OBS 许可证。`node_modules`、`runtime`、`dist` 由安装与构建准备；`data` 保存本机赛事资料、上传素材、配置和录制视频。历史版本、旧截图与验证材料已移出项目目录。已有本机数据继续使用，克隆仓库后首次启动会创建新的本机数据。

RiftCast 面向 Windows 国服、自定义比赛和本地观战。当前提供可运行的桌面控制台、赛事资料管理和供 OBS 使用的 1920 × 1080 浏览器画面，覆盖赛前、BP、局内和赛后的制作流程。转播包装统一为 **RiftCast ARENA**：墨蓝与石墨底色、暖白文字、薄荷强调，以及清楚的蓝红方身份。局内底部采用五行纯黑不透明计分板，两侧选手窗口支持上传图片或 OBS 摄像头，左下角版本可修改，游戏原生英雄面板和小地图保留。使用方法见 [局内底部计分板](docs/局内底部计分板.md)。首次启动使用演示数据，可以先排练流程，再连接本机英雄联盟客户端。

当前代码包含实际的本地接口适配器与观战经济数据桥。真实客户端能提供的数据受游戏阶段、观战模式和版本影响，连接状态、采样来源及缺失数据会在控制台显示。完整功能范围、接口限制和后续模块见 [功能与接口](docs/功能与接口.md)。

ARENA 将工作台、场景卡和节目输出纳入同一视觉系统。工作台的「转播视觉」卡保留计分板、十人装备表与公告字幕快捷开关；「连接与输出 → 包装」集中管理品牌、资源显示、缩放和倒计时。旧配置中的 `worlds2025` / `lpl2025` 在读取时自动归一为 `arena`，原赛事资料、素材、记录与开关继续保留。设计与兼容说明见 [ARENA 视觉更新](docs/ARENA视觉更新.md)。

工作台按三级画幅整理为左侧节目、中部预监、右侧临场任务与底部场景库。Windows 桌面内置模式为节目嵌入 OBS 原生投影；主预监可启用原生动态显示，PVW HUD 为 30 FPS，实际显示跟随 OBS 合成配置并需在目标机器测量。默认预监与设置页仍采用每秒 1 帧快照。跨页常驻播出控制提供整体切入、返回比赛、关闭分析与应急入口。顶部「赛事准备 → 连接检查 → 预监切入 → 赛后收尾」串联完整制作流程。具体操作与本次验证范围见 [单屏导播与制作流程](docs/导播工作流.md)。个人累计金币 OCR、静默启动及历史原生性能记录见 [实时预览与个人经济](docs/实时预览与个人经济.md)、[原生预览性能](docs/原生预览性能.md)，Riot 官方字段核查见 [经济接口说明](docs/riot-economy-apis.md)。

## 启动

当前交付为源码项目和桌面启动入口，需要 64 位 Windows 和 Node.js 22.12 及以上版本，推荐 Node.js 24。桌面窗口由项目内的 Electron 启动，官方 OBS Studio 便携版由启动入口自动准备并作为内置合成引擎运行。无需单独安装或手工配置 OBS。英雄联盟用于真实接入；演示模式可以单独运行。

在项目目录双击 **启动导播.vbs**，即可打开桌面工作台，全程隐藏准备终端。原有 **启动导播.cmd** 入口继续可用，调度后立即退出。首次运行自动安装项目依赖、下载 Electron 桌面运行环境并构建界面，准备日志保存在 `%LOCALAPPDATA%\RiftCast\logs\launcher.log`；启动失败会弹窗说明原因和日志位置。运行阶段的日志可通过桌面菜单“帮助 → 打开启动日志”查看。使用 `启动导播.cmd -Console` 可打开诊断终端。对应实现见 [启动脚本](启动导播.ps1)。

需要指定启动选项时，在项目目录打开 PowerShell：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\启动导播.ps1
```

安装依赖、下载桌面运行环境及首次加载官方英雄图片需要网络。Electron 下载会使用已有的 HTTP(S) 代理；官方发布源失败时，启动脚本会尝试 npmmirror，并按 Electron 包中的官方校验和验证文件。该过程仅使用当前进程环境，不会修改用户的 npm 配置。后续运行复用已安装的桌面环境和已构建的界面。修改代码后，用 `-Rebuild` 重新构建。

也可以手动执行：

```powershell
npm ci
npm run build
npm run desktop
```

浏览器运行方式：

```powershell
npm start
```

服务就绪后打开 [本地控制台](http://127.0.0.1:3888)。浏览器方式可在“连接与输出”点击启动内置引擎；首次需要运行 `npm run setup:obs` 准备运行时，或使用 `启动导播.ps1 -Browser`。用 `Ctrl+C` 停止终端启动的服务。桌面窗口会自动启动缺少的服务和内置引擎；如果已有同一项目服务，它会复用。关闭桌面窗口会停止由该窗口启动的服务及其内置 OBS；正在推流或录制时会提示确认。

开发模式：

```powershell
npm run dev
```

打开 [开发控制台](http://127.0.0.1:5173)。需要用桌面窗口调试时，在另一个 PowerShell 执行：

```powershell
$env:RIFTCAST_DEV = '1'
npm run desktop
```

## 完成一场比赛的基础制作

1. 打开“赛事与素材”，填写赛事、赛程、队伍、选手、比分，上传队标、选手照片和其他图片。按赛程载入比赛，并确认蓝红双方的名称与选手顺序。
2. 在“连接与输出 → 包装”设置计分板、装备表、字幕与品牌，保持演示模式，依次预览待机、首发、BP、局内、选手数据、赛程和赛后画面。编辑先保存到待播，核对 PVW 后点击整体切入；节目使用独立已播配置，同局实时统计持续更新。同场景可以重复 TAKE 应用新资料，临场字幕可使用明确的立即播出与撤下操作。
3. 打开“连接与输出”，进入真实数据模式，指定本机客户端的 `lockfile` 路径，点击 LCU 与 Live Client 连接按钮并检查状态。选人阶段同步 BP；游戏运行时读取局内数据。运行观战或回放客户端的导播主机需与本地服务在同一台电脑，其他设备通过该主机的工作台协作。
4. 在“连接与输出 → 准备直播引擎”确认内置 OBS 已连接。软件自动创建 1920 × 1080 画布；硬件编码默认 60 FPS，软件编码回退为 30 FPS、英雄联盟游戏捕获、透明 HUD 与系统音频。进入比赛或回放后核对合成快照；需要解说时启用麦克风并选择设备，点击“应用画面与音频”。随后在同一面板的「直播平台接收地址」应用本次 RTMP 配置，通过「进入导播台」返回工作台。
5. 在工作台选择 HUD、字幕、倒计时与场景，再通过预监确认布局、切出。客户端缺少双方累计经济时，在“团队经济来源与校准”点击“自动定位经济区域（3秒）”，立即显示游戏顶部比分条；成功后会保存区域并启用 Windows OCR，也可手动填写区域或金币。游戏留在后台或另一屏时，只要采样区域完整可见且无遮挡，就可持续读取。经济显示标注采样来源，超过 10 秒的样本会失效；核对真实读数后再切入节目。操作见 [回放与经济](docs/回放与经济.md)。
6. 在工作台点击“开始录制 / 停止录制”，视频保存在 `data/videos`，默认使用 MKV。赛后保存比赛记录，并导出 JSON / CSV，用于复盘与整理。记录保留已采集的统计、事件、团队经济及采样来源；CSV 也包含团队经济与曲线采样。

节目预监切换控制 RiftCast 图层，内置 OBS 将其与游戏捕获、音频合成。Electron 桌面内置模式的节目区域嵌入 OBS 原生投影，随窗口布局调整位置和大小；预监保留独立 HUD，默认每秒 1 帧，可启用主预监原生动态显示。连接与输出中的节目快照同样每秒更新。硬件编码及合成默认 60 FPS，可在停播时选择 30 FPS。浏览器运行和外部 OBS 模式的节目使用每秒 1 帧的兼容截图预览。内置引擎采用独立便携进程，WebSocket 端口与随机鉴权由软件管理，配置位于 `runtime/obs-studio/config`，保留现有 OBS 安装的配置。当前界面提供游戏捕获、系统音频、解说麦克风、RTMP 输出和录制；摄像头及复杂音视频来源可使用“外部 OBS · 高级”模式管理。该模式仍支持填写 WebSocket 地址、密码与切换场景。[OBS 便携模式](https://obsproject.com/kb/portable-mode)、[OBS 官方远程控制说明](https://obsproject.com/kb/remote-control-guide)

## 全局 BP、局内与团战

本场可选择普通 BP、双方全局禁选、本队全局禁选与有理由的例外局。BP 按选择顺序播出，预选标注未锁定，英雄交换后人工确认最终选手与分路。人工接管支持对照客户端、回退、清空和重启续接。已采集的每局最终阵容会自动保存到系列历史。BP 的 GAME 3 会在本局 BAN 上方显示 GAME 1 / GAME 2 已选英雄；换边后按战队身份映射。局间在「BP 与阵容」点击「下一局」，全局已用英雄自动禁选。新比赛使用「新系列赛」或载入新的赛程。

局内布局增加选手焦点、原生 HUD 处理和游戏小地图保留区域。「连接与输出 → 游戏原生 HUD」可选择自动隐藏回放面板或 OBS 遮挡。开启团队经济 OCR 时保留游戏比分输入，在 OBS 输出上遮挡原生比分。

工作台提供「团战视图」（T）和「十人经济排行」（G），先预监再按 Enter 切入。团战视图完整透出游戏捕获，取消黑底、状态贴图、选手照片及其他赛事包装；切入后在游戏观战窗口按 A，使用原生底部英雄栏和小地图。该场景免除自动 HUD 隐藏及 OBS 遮挡。经济排行按双方十名选手的累计金币统一降序排列，前五在左列、后五在右列，显示英雄头像、经济条和完整数字。局内选手画面支持五组对位手动切入及每 5 秒自动轮播；BP 与首发直接调用随仓库附带的 173 位英雄裁切素材。

操作与验证边界见 [全局 BP 与局内场景](docs/全局BP与局内场景.md)、[十人经济排行](docs/十人经济排行.md)、[英雄原画素材](docs/英雄原画素材.md)、[选手画面](docs/局内底部计分板.md)、[推流流畅性](docs/推流流畅性.md)。

## 哔哩哔哩直播姬第三方模式

在“连接与输出 → 输出 → 直播平台接收地址”中，填写直播姬当次显示的服务器和推流码，点击「应用推流配置」，再进入导播台完成预监与切入，点击「开始推流」。OBS 的连接和来源由内置引擎自动完成。直播姬第三方模式及直播间上线仍按平台要求操作。

制作链路为：**RiftCast HUD + 游戏画面 / 音频 → OBS 合成 → RTMP 发送至直播姬 → 哔哩哔哩直播间**。文档示例为“服务：自定义”、服务器 `rtmp://192.0.2.10:1935`、推流码 `example-stream-key`；每次使用请复制当次直播姬界面的值，服务器与推流码分别填写，保持原值。

内置引擎自动加载 RiftCast 浏览器来源。外部兼容模式也可向已选择的 OBS 场景添加 1920 × 1080 的 HUD；新添加的场景项按当前画布等比居中适配，复用已有场景项时保留布局。工作台显示 OBS 推流、重连与丢帧状态，直播间上线状态需在直播姬和 B 站确认。推流码仅用于本机临时表单，不进入项目状态或数据导出；配置应用后由 OBS 自身保存。操作步骤与官方依据见 [Bilibili 直播姬接入](docs/Bilibili直播姬.md)。

## 图片和数据

上传图片保存到项目的 `data` 目录。在“赛事与素材 → 图片素材”上传后，可在战队资料中绑定队标及各首发选手的照片；队标用于比分画面，选手照片用于“首发对位”场景。在“连接与输出 → 包装”选择“赞助商图片”下拉项并保存，再核对预监并切入，可将上传的品牌标志送到节目输出，未选择图片时使用品牌文字。

英雄图标、立绘、装备图标和装备名称使用官方 Data Dragon 数据；首次请求会加载资源，离线或版本资源不可用时界面保留图片占位与可用名称。客户端提供装备槽位时保留六个装备栏的空位和独立饰品栏。装备价值使用对应静态资源版本的购买总价，选手累计经济由可用的客户端字段提供。

比赛配置、素材和已保存的记录均保存在本机。备份项目中的 `data` 目录可保留这些内容；分享数据时使用导出功能。客户端凭据和 OBS 密码属于本地连接信息，导出的比赛资料用于统计交换。

## 局域网协作

默认只监听本机。需要手机或另一台导播电脑时，先关闭已有本地服务，再显式开启局域网模式：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\启动导播.ps1 -Lan
```

也可在启动服务前设置 `$env:ENABLE_LAN = '1'`。连接设置提供协作地址和访问凭证，先建立主导播席，再由主机生成只读、资料、字幕、回放或主导播席位邀请。手机默认进入资料席；节目切入与局号推进由当前控制席执行，接管需要填写理由。另一台电脑可使用邀请地址协作，旧表单由配置版本检查拒绝，重复请求按 ID 去重。同一服务通过 WebSocket 同步状态。

脚本保留 Windows 当前防火墙配置。如现场网络拦截连接，需要自行允许当前服务端口。协作凭证可以操作导播状态，请仅交给现场工作人员。首版采用局域网 HTTP，适合受控现场网络。

## 当前边界

- 实时 KDA、补刀、等级、装备、BP 和事件使用接口实际返回值。本机已读取 10 名玩家的 Live Client 数据，并检查其 Swagger；当前公开字段缺少选手累计经济和 XP。团队经济可由观战比分板 OCR 或人工校准补充，样本具有来源、采样时间和 10 秒有效期；个人累计经济保留缺失值，XP 排行仍缺少来源。
- 实时胜率模型、阵容强度模型、自动跟随比赛镜头、历史 PB% 和英雄池画像仍待扩展。界面中的赛事历史只来自本机录入或保存的比赛资料。
- 正在播出的比赛来源受到服务端保护，Replay 暂停、跳转和倍速写入会被拒绝。直播精彩回放使用 OBS 独立缓冲片段，支持保存、预监、入出点、声音组合和立即返回比赛。离线 Replay 控件操作本机回放播放状态，需启用 Replay API 并重新打开录像。本机已修复未启用开关导致的 HTTP 404，重开回放后播放接口返回 HTTP 200、诊断结果为 `ready`。回放设置、备份位置与现场操作见 [回放与经济](docs/回放与经济.md)。截图中的引擎名称属于参考需求，当前未接入该品牌的服务或模型。
- 国服云战绩服务、职业赛事专用数据流和自动开房未包含在首版。局内两侧选手摄像头通过 OBS 视频采集来源配置，物理设备效果需现场核对。
- 本机回放读取已实测。完整自定义 BP、暂停 / 倍速 / 跳转的现场效果、OCR 在目标观战布局中的识别准确率及真实 OBS 推流链路仍需按 [验收说明](docs/验收.md) 逐项演练。游戏版本更新后请复核本机字段与画面布局。
