# OB 全流程改进落地与现场验收 · 0.3.0

发布日期：2026-10-07。修改规格：[OB 全流程改进建议](OB全流程改进建议-2026-10-06.md)，原基线提交 `604ba83510bdb8370eed8b88308ff42ac056a9de`。

本版完成规格中的播出隔离、比赛身份与结果一致性、音频基础控制、独立片段制作、故障处理和协作权限。功能代码与自动验证已交付。真实游戏、物理设备、平台接收和连续 30 分钟性能需要按本文最后的清单进行现场验收。

## 操作顺序

1. 在「赛事与素材」准备赛程、战队、选手稳定 ID、播出名称、游戏账号和本地照片。游戏账号填写接口实际返回的账号名称或唯一 ID，须能唯一匹配本队选手。按住载入比赛，核对系列赛、局号、尝试号、双方战队和 BO 比分。
2. 在「连接与输出」准备游戏来源、解说设备和本场输出。工作台的比赛日检查分别记录身份、游戏来源、本局样本、音频试录、磁盘、节目音画和平台回看，共七项。确认者与时间保留在状态中，来源或身份变化会使相关检查失效。
3. 修改标题、战队资料、字幕、包装和选手画面后，在 PVW 核对。点击「整体切入」或 `Control+Enter` 后应用整份配置；相同场景也可以重新 TAKE。节目使用独立的已播版本，同一局的实时游戏统计继续采样。连接 OBS 时，来源准备成功后发布新 PGM；来源失败保留旧节目并显示失败。OBS 未连接时显示请求状态，接上引擎后仍需核对画面。
4. 普通 BP、双方全局禁选、本队全局禁选及有理由的例外局均可配置。BP 按 B1/R1 选择顺序播出，预选注明未锁定。英雄交换后确认选手、英雄和分路，保存到待播，再 TAKE。人工接管不会被客户端轮询覆盖，可对照最新客户端样本、退回一步、清空无效 BP，并在重启后继续人工 BP。
5. 局内分析按设定的 3–120 秒时长播出，到时返回比赛；也可随时使用「关闭分析」。团战视图保留游戏原生区域，选手画面自动轮播在保持、暂停、回放或团战时停止。比赛来源供 PVW 与 PGM 共用；本版没有第二个独立游戏镜头。
6. 赛后核对胜方与终局样本。确认胜方、完成终局处理且 BO 仍未结束时，用任一「下一局」入口推进。下一局准备不会清空此前 PGM。局间换边时比分、照片和摄像头配置跟随战队 ID。新系列赛按住执行，默认从 GAME 1、0:0 开始。

## 声音、片段和应急画面

游戏与解说的音量、静音、监听和同步偏移可以在输出期间调整。音频设备、编码、采集拓扑与录制音轨配置须在停播维护窗口修改。监听使用独立耳机；先录制 30 秒并回看，确认桌面音频没有再次采集监听返送。三轨方案为轨 1 成品、轨 2 游戏、轨 3 解说。采访与音乐预留总线状态，实际来源需提前在 OBS 准备。

OBS 回放缓冲初始为 60 秒。保存片段后先「预监」，读取文件时长，再填写入点、出点与声音组合。原声策略关闭现场桌面声音与解说；现场解说策略关闭片段音频，保持已确认的解说状态。进入片段后禁止重准备正在播出的媒体；到出点或媒体结束时返回游戏并恢复之前的声音状态。片段场景包含已录的原比分/时钟与 REPLAY 标识，实时 HUD 不添加到该场景。

HTML 视频预监依赖浏览器支持的媒体封装与编码。MKV、特定编码在浏览器中无法播放时，应在 OBS 中预监或将片段转为可播放的本地文件再使用。OBS 媒体准备和现场画面/声音的人工核对分别完成，自动检测到时长不代表操作员已经验过画面。

内置 OBS 在启动前准备原生图片技术暂停场景及 `Ctrl+Alt+Shift+P` 全局快捷键。该备用画面直接读取本机 PNG。浏览器、HUD 服务或主工作台异常时，导播可使用 OBS 的本地快捷键。已有内置 OBS 进程需要在停播窗口重启一次，才能加载新增场景与快捷键。外部 OBS 模式须自行准备本地备用场景和快捷键，并保留明确的比赛来源场景。

## 离线准备与兼容基线

| 项目 | 本版基线 |
| --- | --- |
| 桌面系统 | 64 位 Windows；本机字体 Microsoft YaHei / Arial |
| Node.js | 最低 22.12；本次自动验证使用 24.12.0 |
| Electron | 锁文件固定 44.5.1；按原启动入口准备 |
| 内置 OBS | 官方便携版 32.2.2，校验信息在 `scripts/obs-runtime.json` |
| Data Dragon | 随包英雄资源 16.19.1；本场额外图标按填写的 x.y.z 版本缓存 |
| 游戏与 OCR | 游戏补丁由导播填写；OCR 基线 spectator-1920-v1、1920 × 1080，更新后重新校准 |

首次联网安装依赖与运行时，准备本场资源并构建：

```powershell
npm ci
npm run prepare:offline -- 16.19.1
npm run build
```

随后上传队标、照片、品牌图片，在比赛日检查点击「检查全部素材」。清单提示缺失文件、远程图片、随包英雄版本与缓存数量。远程照片须先上传到本机；字体和中文排版在目标机器核对。资源准备显示有失败项时，修复网络后重复准备直到全部完成。版本更新、下载和 OCR 调整安排在场次之间。

断网运行可在 PowerShell 设置 `$env:RIFTCAST_OFFLINE='1'`，再用同一终端执行 `启动导播.ps1`。素材接口仅读取本机缓存，未缓存的装备/技能/符文保留占位。游戏来源和直播平台的网络需求按现场环境确认。动态原生预监仅在 Windows Electron 内置 OBS 模式启用；原生投影跟随 OBS 实际合成帧率，PVW 浏览器层目标为 30 FPS，浏览器与外部模式保持快照核对。

## 保存、导出与恢复

状态位于 `data/state.json`，上传素材位于 `data/uploads`，静态缓存位于 `data/resources`，默认录像位于 `data/videos`。状态保存失败会显示错误并拒绝“已保存”响应；内存中的最新资料仍可导出赛事包。需要先保存恢复材料，再关闭异常服务。

现场录像索引记录系列赛、局号、尝试号、文件路径、文件大小、开始/结束游戏时间及视频秒数。连续录制跨局时，TAKE 新局会产生对应的文件时间段。文件存在与大小可自动检查；可播放性、声音与片头片尾由导播回看。游戏暂停与现实录制时长按各自时钟解释。

重赛作废档案保留原阵容、结果、尝试号和裁判理由，旧记录导出标明已作废。修订有效胜方会更新 JSON、CSV、赛程及 BO 状态。终局来源到达与十人统计/经济完整度分别保存；选择采用末次不完整观测值时，必须填写理由。快捷快照列表保留最近 100 条，有效结果及赛事包继续保留完整结果快照和视频/片段索引。

维护前先停止输出并正常退出，用另一个目录完整备份 `data`；如需保留 OBS 自身设备/输出配置，另行备份本机 `runtime/obs-studio/config` 并作为私密资料保管。恢复时先退出服务，保留当前目录的可恢复副本，再用已确认的备份恢复整个 `data`，重新启动、核对身份/来源/声音，并在 PVW 重确认后 TAKE。恢复过程中不要混用两个场次的 `state.json` 与 `uploads`。席位令牌仅存在于服务内存及浏览器会话中，重启后重新建立席位。导出包不包含 OBS 密码、推流码或席位令牌。

## 自动验证与现场验收

自动验证覆盖状态与规则、真实隔离 HTTP 服务、临时文件、OBS RPC 模拟及浏览器流程。复现命令：

```powershell
npm test
npm run check
npm run build
# 安装 Playwright 或用 RIFTCAST_PLAYWRIGHT_MODULE 指向已安装模块
npm run verify:production
```

本次 `verify:production` 检查八个流程，截图与报告输出至被 Git 忽略的 `verification-output/production-0.3.0`。测试使用隔离目录、演示数据及静态资源回复，没有读取操作员赛事资料，也没有启动真实 OBS。

正式交付现场验收采用一场 BO3 排练，保存节目录像、原始观战参考帧、状态日志和平台回看。逐项检查：赛前断网及错误设备，BP 预选/交换/人工接管，节目中修改下一场资料，镜头与跨页快捷键，统计缺失/恢复，独立回放同时出现下一次团战，真实讲话/监听/分轨，摄像头拔插，网络限速与重连，本地备用画面，结果改判/迟到终局样本，换边/旧样本，重赛，保存失败及结束后重启，多席位并发。

性能验收要求游戏、实际 HUD、所需摄像头、OCR、录制与推流共同运行至少 30 分钟，分别观察实际显示、渲染、编码、网络和平台播放。自动测试与构建不能替代这项现场证据。自动跟随镜头、胜率/阵容模型、第二路观战源、慢速/多角度及独立回放机保留为规格中的后续能力。
