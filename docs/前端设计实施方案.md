## 设计计划

这是导播在一块低高度屏幕上完成比赛制作的工具。记忆点是两台清楚的监视器、紧接其下的节目交接台，以及真实通道的纵向推子；品牌、导航和设备诊断都让出主位。界面按“操作哪一层事实”分区，而非按功能数量堆卡片。

颜色按任务书建立六个基础色：底色 #11151B、工作面 #181E26、控件面 #222A34、正文 #EFF3F7、次文字 #ADB8C7、品牌 #70D7C2。浅色分别 #F2F4F6、#FFFFFF、#E8EDF2、#17212C、#536273、#146E61。PGM 红、PVW 绿、选中蓝、焦点蓝、警告琥珀另有语义变量。颜色只传递状态，所有关键状态有文字。节目变量独立，不读取操作端主题。

字体使用本地 Segoe UI / Microsoft YaHei / PingFang SC；14px 正文、12px 辅助、16px 面板主信息、20px 领域标题。比赛时间、比分、通道 dB 用等宽数字。层级通过位置、字重和分隔建立，不用新的装饰字体、无意义编号或营销标题。

主要导航保留七个 hash；56–64px 左轨和单行比赛栏。全局播出与应急条放在窗口底部，成为所有页面稳定的出口；详细回执在主工作台与核对弹层说明。管理/设置页仍能直接返回比赛和应急。工作区内部滚动，全局条保持可达。

图层编辑是一张完整工作面：场景名与保存动作在顶栏；左边图层排序，中间有工作留边的画布，右边按“变换、适配、来源”分组；添加来源是明确打开的来源面板，不把全部选择器常驻挤在图层列表后。底部只说明草稿/待播/节目关系。点选、拖动、八向缩放、方向键和数字输入共用1920×1080坐标；精确数学和旧范围保留。

连接与输出是路由工作区：左侧任务目录（数据、画面、声音、输出、包装、诊断、协作），右侧当前任务。输出从 Program 源出发，分成视频与最终音轨1两条线路，落在接收设备；设备准备与诊断按需展开，启动与独立停止集中在固定动作区。RTMP凭据只留内存，运行状态不依赖当前选择。单通道混音与 Program 总线同时可观察。

其余领域沿同一任务语言重新决定构图：BP 是当前回合、双队槽位和搜索英雄侧面板；数据是十人比较表与采集状态；管理是对象列表加详情；收尾是胜方与冻结报告核对再到归档/下一局；帮助是故障到真实入口。移动首屏是身份、当前控制者、一个可切换监视器及角色任务，底部仅放有权执行的动作。节目端按1920×1080建立独立身份栏与对阵排版，11场景和动态custom逐项迁移；团战透明和局内五行黑底的坐标契约优先，未实机核对前不移动其几何。

## 对照 brief 的自审与修改

最初“保留顶部状态带、监视器下方再放状态、每通道一横条”的草图，仍然近似之前检查点，会重复状态并压缩低高度画面。因此改成底部全局安全条、监视下方交接工作面、右侧并排推子。不是为了变化而移动：眼睛从画面到TAKE距离短，手能持续调整三个通道，管理页也有固定应急出口。

编辑器若只换三栏宽度仍是已有方案，故重新分离添加来源与图层编辑，顶栏集中命名和保存，属性按当前对象组织。输出若只画箭头仍无法理解行动，故将来源、传输、接收和启动/恢复安排成对应的区域，并让未知事实明确占位。

基础色接近技能所述常见深色默认，但这是用户明确指定的播控方向；保留它，把设计差异投入工作关系与内容组织。禁用玻璃、发光、营销英雄区、假数据和装饰编号。说明句写在会影响决定的地方，正文不反复解释实现。
