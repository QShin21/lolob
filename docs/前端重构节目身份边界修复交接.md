## 两项缺陷的实际改动

上次 TAKE 是 Aatrox，合法自动更新已经显示 Gwen；随后手工保存 Akali，再恢复客户端 Aatrox 时，现在 **BP 卡片和首发对位均保留 Gwen**。待播保留 Aatrox，下一次明确 TAKE 才发布，之后新的自动样本照常推进。

- 增加 `production.programRosterHold`，在人工接管前与 BP 保留值一起，从同一份当前节目视图取得玩家。保留选手 ID、成员集合、姓名、照片、英雄、英雄名称、队伍及分路；不会退回较旧 TAKE 的英雄，也不会用选择顺序推测归属。
- 同局统计按稳定选手 ID 合并。KDA、补刀、经济、装备、生命和采样有效期继续更新；比赛时间、队伍统计也继续更新。缺失选手保留最后样本及其原有有效期，不把新增替补或换位后的数组位置当成原选手。比赛身份或重赛尝试变化后不借用新局统计。
- 归属编辑也在修改玩家前建立保留值，覆盖重复交换、修改分路、取消映射；这个入口不暂停正常自动 BP 卡片。BP 恢复自动则保持整个接管边界，等待 TAKE。
- 准备中的切入不清除保留值；成功发布才同时释放 BP 和玩家保留。撤回/重做同时恢复此前实际可见的玩家和 BP。字段沿现有状态文件持久化。
- 待播 BP 比较当前有效节目内容，并计入仍等待 TAKE 的来源恢复。即使恢复样本恰好等于原 TAKE，或英雄暂时相同而同步尚未恢复，也不会显示零变化。英雄归属摘要排除统计字段和样本排序；正常自动采样、轮换计时及重启等待采样不计作编辑。

按任务书第 357、359、463 行，允许的自动 BP 和同局实时统计继续更新，人工待播配置等待 TAKE；两项要求不存在冲突。本轮没有改 LCU/Live Client 的采集流程、CAS、requestId、权限，或 requested / applied / confirmed 回执语义。

旧版本若只保存了 `programDraftHold`，没有保存当时玩家身份，就无法可靠还原那一刻的完整名单。兼容路径使用最后接受的玩家快照，不从 pick 顺序猜人、不读最新待播名单。旧撤回记录同样使用已存节目玩家；本轮新建保留值和撤回记录都保存完整身份。这项历史数据限制仍需升级后核对画面，不能宣称已从缺失数据恢复原名单。

## 所有节目消费者的核对

| 场景或入口 | 共享状态使用及本轮检查 |
| --- | --- |
| draft | 卡片选择来自保留 draft，姓名/归属来自同一节目玩家；实际组件静态渲染比较通过 |
| lineup | 英雄、照片、分路与左右队伍均来自保留玩家；合成 LCU 采集路径及实际组件比较通过 |
| live | 黑底五行、选手画面标签通过同一玩家身份；统计继续推进；未改任何几何或装饰 |
| gold-ranking / economy | 排行保留玩家身份、经济继续按样本更新；曲线、队伍统计未冻结；实际组件比较通过 |
| ranking 十人 / 焦点 | 十人组件使用节目玩家。另发现焦点组件二次读取赛后归档会绕开保护，现按 programme bus 直接使用已解析节目；新增“新归档含待播名单”的渲染回归 |
| postgame / interview | 节目玩家与已接受比赛身份保持一致；节目个人名牌、队伍归属按当前节目解析；实际组件比较通过 |
| standby / schedule / teamfight | 不直接渲染玩家名单，十一场景同批比较通过；团战仍为空透明层 |
| custom:* | 图片/窗口/共享 OBS 来源不消费玩家身份，沿用既有场景 TAKE 快照；本轮无相关实现改动 |
| /overlay、桌面 PGM、/remote PGM | 输出路由原本明确传 programme bus；补齐桌面及手机排版监视器的 bus，避免被当作 PVW 再读取归档。PVW、数据页和归档预览仍使用其待播/归档路径 |
| OBS 选手画面 / 回放归属 / 原生 HUD | 沿用 `programState` 后再解析的路径，代码追踪确认；没有操作真实 OBS 或原生窗口 |

这里的渲染检查执行实际 React 场景组件的静态输出，不运行浏览器效果或设备，不代表视觉尺寸、资产解码、OBS 合成或观众端通过。桌面和手机 PGM 排版仍须 Sol 在真实浏览器复验。
