# 全局 BP 与局内场景

在「BP 与阵容」中选择本系列的对阵与局号。LCU 完成十名英雄的锁定后先保存候选阵容，确认进入 GameStart / InProgress 再自动登记；观战接口取得完整实际阵容时也能补记。预选、取消的 BP 不登记。每局开始后无需手动抄写英雄。

局间点击「下一局」，上一局英雄自动进入全局禁用。GAME 3 的画面会在本局 BAN 上方分别显示 GAME 1 与 GAME 2 的已选英雄。系统禁用范围包含此前双方已用英雄；历史显示按战队 ID 跟随换边。手动选择此前已用英雄会被拒绝。局号由导播推进，可在赛事资料中调整；系统自动保存已采集的阵容。新系列使用「新系列赛」或载入新赛程，旧记录仍保留。只有已接入或已确认的比赛能产生历史，软件无法还原未采集的旧局。

导播工作台提供以下局内场景。选择场景进入预监，按 Enter 或「切入节目」后播出。

| 快捷键 | 场景 | 内容 |
| --- | --- | --- |
| 4 | 局内计分板 | 顶部战队、击杀、团队经济和比赛时钟；底部十人装备、补刀和 KDA；左下选手焦点及品牌；右下保留游戏小地图 |
| T | 团战视图 | 完整透出游戏原生画面，切入后在游戏观战窗口按 A 切换视角；保留游戏自身的底部英雄栏和小地图 |
| G | 十人经济排行 | 双方统一按累计金币降序排列，前五左列、后五右列 |

团战视图已取消底部黑色遮挡、十人状态贴图、选手立绘与焦点面板、两侧选手栏、顶部计分包装、小地图边框、赞助商和字幕条。OBS 浏览器图层在该场景完全透明，画面由游戏捕获提供。工作台按 T 预监、Enter 切入，再到游戏观战窗口按 A。若此前自动隐藏过原生 HUD，切入团战时先恢复软件接管前的开关，之后保留游戏内手动选择的视角。预监与节目共用同一游戏捕获，原生 HUD 恢复在团战切入节目后生效。

其他局内场景统一使用 ARENA 包装。左右人物栏和对应侧边遮挡已移除，选手信息集中在底部十人装备表与左下选手面板，详细选手数据按需调用，两侧保留游戏视野。标准 Live Client 无法保证十名选手的生命 / 资源和技能冷却均可用，软件不推算缺失字段。累计经济排行见 [十人经济排行](十人经济排行.md)。

「连接与输出 → 游戏原生 HUD」提供三种模式：

- 自动模式：局内包装场景切入节目后尝试使用 Replay API 的 `/replay/render` 隐藏原生计分、选手面板、目标详情、聊天、公告和时间轴。保留游戏小地图、场内血条及世界渲染。切入团战视图、退出局内节目、关闭自动模式或工作台正常退出时恢复原开关。
- OBS 遮挡：自动接口不可用时启用，计分板开启且确有需要时使用顶部最小比分遮挡。左右侧边与底部整块遮挡已取消，底部只由实际数据组件覆盖各自的区域。顶部区域按用户提供的 16:9 默认 HUD 校准，游戏 HUD 缩放或窗口比例改变后需核对合成画面。可在游戏内手动隐藏两侧原生面板与聊天，进一步释放场内视野。
- 关闭处理：恢复软件接管前的回放开关，不使用原生面板遮挡。

团战视图在上述三种模式下均保留原生画面，不应用赛事遮挡，也不持续修改游戏 HUD。快捷键 A 需要在游戏观战窗口中操作。

开启团队经济 OCR 时，自动模式会保留游戏窗口自身的比分供识别，OBS 的顶部遮挡防止两套比分同时出现在直播。OCR 采样输入仍为游戏画面，采样失败时应检查采样区与游戏 HUD 的真实位置。

Replay API 必须已经可用。当前版本若缺少开关或未确认写入，工作台显示备用遮挡状态。接口字段依据 [Riot Replay 文档](https://developer.riotgames.com/docs/lol#replay-api) 与 [官方 League Director](https://github.com/RiotGames/leaguedirector/blob/main/leaguedirector/api.py)，仍需在目标观战或回放版本核对。

本轮 UI 验证使用隔离的演示状态及用户提供的静态参考画面，不会启动游戏或推流。截图为布局证据，Replay HUD 实际隐藏效果需在已启用接口的游戏进程中核对。
