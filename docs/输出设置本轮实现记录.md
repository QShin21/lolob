# 连接与输出本轮实现记录

本轮依据最新完整任务书（Library `libfile_fa8f64dc18bc8191840dd744c317798c`，493 行、58822 字节）及《前端设计实施方案》，逐段完整阅读后实施。使用固定版本的 frontend-design 设计流程，先比较工作关系，再重排 DOM 与组件自身样式。先前界面仅作为功能盘点来源。

## 设计方向和自审

这块工作区的核心不是表单数量，而是导播能否回答：从哪一路节目取信号、经过什么设备、谁负责接收、目前究竟运行了什么。方案采用常驻任务目录与连续工作面；输出从左边唯一的 PGM 源分成视频和最终音轨 1，再连接设备与接收端。48 kHz 双声道的 CABLE Input 送出端、CABLE Output 伴侣接收端保留准确命名。

初稿若继续在右侧放三步启动向导，会把短而高频的启动动作推到长说明后，也使窄屏将路由挤成一列。因此取消旧右列，运行事实和独立停止放到任务顶部，启动动作紧接信号图；接收核对、完整组件事实及采样诊断下移。设备不就绪时展开准备区，但准备区不把启动和停止挤到末尾。

另一处修订是把“查看另一条输出路径”与“修改引擎目标”分开。RTMP 与伴侣页签只切换本地工作区；若与引擎配置不同，显示“设为下一次输出”。该按钮才调用原有 destination 接口，仍受本地主机、控制权、活动输出和未知设备状态约束。实际 RTMP、视频、声音和录制状态始终显示，查看别的路径不能将活动输出隐藏。

采用共享 `--ui-*` 变量、系统字体、20px 当前任务标题、14px 操作文本与12px 辅助说明。对齐和分隔承担分组，不使用装饰步骤编号、卡片套卡片或营销标题。

## 第一轮截图后的修订

已直接查看整合截图 `docs/evidence/frontend-design-round1/new-output-offline-1366x736.png`。原布局能读完音画路径并看到启动，但实际运行和独立停止掉到内部滚动区域以下。这个问题不是靠缩小字体解决：把四路事实和停止/恢复组成一个紧凑区域移至路径选择之前，在桌面任务滚动中保持可见。标题和路径状态在低高度下减少纵向留白，PGM 场景长名最多显示两行并可悬停看全名，设备实际端点单行省略并保留完整提示和诊断信息。

该修订保留来源、设备、接收端的完整两路结构；失败回执和恢复警告仍在停止按钮附近。此次只做低高度构图和信息顺序调整，没有更改设备控制与后端请求。新版由整合者统一重截核对；尚未把改后首屏坐标或设备链路记为通过。

## 已实现覆盖

| 工作区 | 本轮重排 | 保留的实际动作与状态 |
| --- | --- | --- |
| 设置任务目录 | 左侧八项任务，右侧当前内容内部滚动；设置草稿留在原组件内 | 数据、画面、声音、输出、包装、诊断、协作、外观，返回导播台；上下/Home/End 键导航 |
| 数据连接 | 来源切换与三行连接事实；本机配置双列编辑 | 演示/实时、LCU、Live Client Data、Replay API、lockfile/游戏目录选择、轮询与自动阶段、配置版本保存 |
| 画面 | 引擎状态与操作一条栏；节目快照和来源配置并排 | 内置/外部引擎、启动、刷新、1 FPS 周期快照暂停/恢复、游戏窗口、声音与麦克风、帧率、来源应用、来源列表、真实 OBS 统计 |
| 外部 OBS | 连接凭据与场景操作分列 | WebSocket 配置、密码、连接、场景刷新与切换、HUD 来源添加；活动输出保护 |
| 声音 | 采集配置上方显示各路输出事实，下方接原混音工作台 | 原 ProductionDesk 音频、音乐、增益、静音、监听与音轨保护；不重写混音业务 |
| 输出 | PGM 音画线路、启动区、实际运行和独立停止、人工接收核对、设备准备、诊断 | 原 RTMP/伴侣/录制 API；凭据只在内存、成功清空推流码；停止与恢复保持独立 |
| 节目包装 | 身份、基础参数与倒计时分区，底部固定保存到待播 | BroadcastLook、LiveBottomControls、NativeHudControls、GraphicControls、赞助商素材、公告、HUD缩放与开关；原 CAS 和待播语义 |
| 诊断 | 采集诊断与回放控制分列，经济采集独立工作面 | ReplayDiagnostics、暂停/倍速/跳转、EconomySourcePanel 全部校准与采样能力 |
| 协作 | 两类访问链接、网络与操作席位独立入口 | 复制链接、外部画面、remote、局域网刷新、prepare/seats；令牌仅进入原复制行为，不直接展示 |
| 外观 | 独立任务入口 | 原 AppearanceSettings 和主题偏好兼容 |

输出设备事实逐项显示 supported、available、installed、ready、active、managing、需要重启和具体错误。摄像头没有与音频相同的 ready 字段，因此展示驱动注册、状态可查询、视频活动和重新加载要求，不虚构统一“已连接”。

准备入口明确会检查/安装摄像头和基础 VB-CABLE，可能触发 Windows 管理员授权与重启。没有进入页面时的安装、提权、开播或重启副作用。外部平台开播与接收情况始终标为待人工核对。

成功回执保留在当前工作面。伴侣停止必须同时确认视频停止、音频不活动且退出托管；请求失败后只读取最新引擎事实以显示回滚后的状态，不自动重复启动/停止。仍托管而不活动时保留“重试停止并恢复音频”。缺失采样显示未提供，不补零。

## 工程边界

重写 `OutputPatchbay.tsx` / `output-patchbay.css`、`EmbeddedObs.tsx` / `embedded-obs.css`、`Settings.tsx`；新增该页面专用 `settings.css`。这两份组件旧样式已替换，Settings 不再借用 management.css。新页面主类名与旧的 settings-page / embedded-obs-panel 分离，未追加全局兜底样式。

未修改 App、共享 tokens、ProductionDesk、OutputSignals、后端、控制协议或权限判断。设置页额外在输出按钮附近说明当前控制者限制；后端仍是最终权限与版本校验。完整布局及原生画面可见性需由统一集成继续核验。
