# 观战遥测与计分板

## 数据与显示

计分板通过本机 Live Client Data 获取选手、装备槽位、召唤师技能名称、死亡状态和复活剩余时间。国服只读采样器补充生命、资源、累计经验、金币、技能槽位冷却和增益。按队伍与英雄名称匹配十名选手，显示名与选手排序变化不会改变数据归属。

冷却使用游戏时间中的绝对结束时间 `readyAt`，总冷却使用 `totalCooldown`。图标变暗，扇形遮罩随游戏时间减少；剩余时间大于 10 秒时隐藏数字，最后 10 秒向上取整显示秒数。回放暂停时停止转动，倍速跟随游戏时钟；采样过期或回退后状态失效，等待当前画面的新样本。

R 图标来自指定版本的 Data Dragon 英雄资料。未学习的大招显示为灰色，缺失冷却显示为未知。装备按价格重新排列后仍通过原始槽位与装备 ID 绑定冷却。原生读取当前覆盖装备技能槽位；未提供技能槽位的装备被动冷却需要另外适配，不能由装备静态说明推算。充能技能当前显示已读取的可施放冷却，未新增充能层数进度界面。

ID 下方依次为紫色经验、绿色生命、蓝色法力／黄色能量。经验根据当前版本的峡谷累计升级阈值换算，并核对原生等级与 API 等级。非标准经验模式无匹配阈值时保留未知。其他资源类型保留原始资源量。

个人金币移至 ID 与补刀／KDA 之间，分两行显示余额与括号中的累计金币。死亡头像灰度处理，并在中央显示复活倒计时；男爵增益使用紫色框，远古龙增益使用灰白色框，两者同时存在时使用双框。增益过期、死亡或采样失效后移除边框。

## 当前读取配置

- 系统：Windows x64；单个 `League of Legends.exe` 进程。
- 当前已验证游戏文件版本：`16.21.829.9102`，SHA-256：`6CA9446AC4E65A311CB0796B72A459097CDF912A337619D1D1FD207E01AEDD6F`。
- 同时保留 `16.20.824.8524`，SHA-256：`EE3C887B4579AEAB12CA77B2A43CC1CC3411A8AA30BC43D2DFEA856F6CE497C8`。各构建独立选择布局，定位和实测见 [16.21 维护记录](CN-16.21-Maintenance.md)。
- 只在 Live Client Data 返回完整观战名单、没有活动玩家且 Replay API 返回相同进程 ID 时接入。
- 游戏文件校验失败时停止原生采样，继续使用可用的官方 API 数据。设置 → 数据 → 观战遥测显示连接状态。
- 采样器只请求 `PROCESS_VM_READ | PROCESS_QUERY_LIMITED_INFORMATION`，使用有界 `ReadProcessMemory`。不向游戏写内存，不加载 DLL，不安装驱动，不调用游戏内部函数。
- 单个样本包含明确采样时间与游戏时间；原生样本超过 3 秒后失效。游戏升级后需要重新核对字段并增加匹配配置，不能仅修改版本字符串。

原生采样源码位于 `scripts/native/observer-reader.cs`，通过隐藏的 PowerShell 工作进程加载，安装包包含源码与启动脚本，无需另外安装 Python 或 Node.js。进程退出、句柄失效、名单不完整或字段超界均报告不可用。完整原始内存与账号凭证不落盘。

## 伤害数据边界

`telemetryDamage` 支持对英雄伤害、承受伤害、物理／魔法／真实对英雄伤害。`telemetryDamageSource` 记录 `api`、`memory`、`packets` 或 `postgame` 来源。观战逐次伤害用于团战与历史战斗分析，记录 JSON 和 CSV 保留数据来源。

国服 16.20 与 16.21 通过各自的逐次伤害协议读取观战分片。实时观战记录覆盖起点，按当前游戏时间查询；ROFL 回放完成十人官方终局累计校验后开放逐次伤害。对局结束后，可通过同一对局 ID、同队同英雄的官方 LCU 赛后统计补录。详见 [伤害采集记录](Native-Damage-Research.md)。

模拟数据的渲染通过、原生真实读数通过、OBS 合成与平台直播验收是分别记录的验证范围。当前真实采样已验证十名英雄的生命、资源、经验、金币及使用后的召唤师技能／饰品冷却；男爵、远古龙和特定主动装备仍需对应事件发生时的真实画面对照。

# 1.1.5 计分与资源字段核验

国服 `16.20.824.8524` 使用现有 SHA-256 白名单。以下路径通过该版本函数静态分析与运行中的回放连续采样交叉核验；读取器仅使用外部只读访问。

- 选手统计树：`imageBase + 0x1ee9418`，以英雄 network ID 匹配树节点。K/D/A 值位于统计对象 `0x310/0x338/0x360`；小兵、野怪计数为 `0x270/0x298` 的 float。与原函数一致分别加 `0.00001f` 后向下取整，再合计。Live Client 原函数随后截到十位，直读保留精确值。
- 视野得分：英雄对象 `0x53a8` 的 float；与 Live Client `wardScore` 对照验证。
- 中立资源管理器：`imageBase + 0x1ee9298`。蓝队表位于 `0x18`，红队位于 `0x68`，每个条目 8 字节，首 4 字节为累计数量。类型 3/4/5/6/7 对应元素龙/峡谷先锋/远古龙/男爵/虚空巢虫。游戏原生计分栏使用同一管理器。
- 防御塔管理器：`imageBase + 0x1ef3218`；`0x08` 为蓝方被摧毁塔数，`0x14` 为红方被摧毁塔数，按对方被毁数呈现己方摧毁数。

资源计数取当前内存快照，不累计 Live Client 事件列表。回放事件可能包含重复、未来事件或缺少中立资源击杀；当前快照也能随回放倒退重新读取。所有新增字段保持时间戳、有效期与范围检查，缺失样本不生成零值。采集到的六类资源保存在赛后记录中。

## 1.1.7 十人完整符文

同一 SHA-256 白名单构建的 Live Client `fullRunes` 序列化函数提供了读取依据。英雄对象内嵌符文页位于 `hero + 0x4f28`；页内 `0x230/0x238` 为选择数组首尾，每项步长 `0x50`，首指针指向符文定义，定义 `+8` 为 ID。数组前六项为主系四个与副系两个选择，后面三项为属性碎片；两系指针位于页内 `0x198/0x1e8`，系 ID 位于定义起始位置。采样只调用外部 ReadProcessMemory。

读取要求数组恰好九项，六个符文唯一且在本地目录中，主副系合法且不同；接入时按英雄和阵营绑定，并与 Live Client 的基石、主系和副系核对。主系四项和副系两项还需分别属于相同符文系。任何可选符文字段读取失败均不影响生命、冷却等已有字段。

2026-10-22 在正在运行的国服回放中，通过正式 C# 采样、遥测合并及 normalizeLive 全链路核验十名英雄；60 个符文 ID、30 个属性碎片 ID 均与同一回放官方记录一致。脱敏十人样本保存在 `server/test-support/rune-pages.json`，仅供测试；首发对位使用实际 `fullRuneIds`，属性碎片保存在 `statRuneIds`。赛后报告的小卡片保留紧凑排版。
