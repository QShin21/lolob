# 单屏导播与制作流程

适用版本：0.4.1（2026-10-07）。在「连接与输出 → 外观」选择深色或浅色风格，切换后立即生效并在本机保存；节目配色保持稳定。详见 [0.4.1 外观主题说明](外观主题-0.4.1.md)。页面布局见 [0.4.0 前端落地说明](前端改进落地-0.4.0.md)，比赛生命周期见 [0.3.0 全流程说明](OB全流程改进落地-0.3.0.md)。

工作台分为节目、预监、临场任务三列。固定栏显示节目/待播身份、配置改动、引擎应用状态、推流/录制摘要和控制席，并提供切入、回比赛、技术暂停。音频、回放、字幕、选手任务在右侧切换；常用场景靠近预监，完整 11 个场景放在下方可筛选的场景库。小屏幕可滚动查找全部场景，常用任务入口保持首屏可达。画面包装、经济卡、阵容和事件收进「画面包装与对局详情」，需要时展开。

## 预览频率

| 位置 | 显示方式 | 更新频率 |
| --- | --- | --- |
| 工作台 · 节目播出 | Windows Electron 内置引擎采用 OBS 原生投影 | 按输出配置使用 60 / 30 FPS；默认硬件编码为 60 FPS |
| 工作台 · 预监画面 | 默认 JPEG 快照；Windows 内置模式可选原生动态显示，保留独立 HUD | 默认每秒 1 帧；动态 HUD 30 FPS，投影跟随 OBS 合成 |
| 连接与输出 · 合成核对 | JPEG 快照，核对当前节目与来源 | 每秒 1 帧 |
| 场景卡 | 场景包装缩略图 | 用于选择场景，与游戏视频采集分开 |

快照按每秒 1 帧的总线节奏更新。页面隐藏、离开页面或手动暂停时停止订阅，恢复后重连。默认预监与设置页使用快照；启用主预监动态模式后可创建第二个原生投影。浏览器与外部 OBS 的节目画面同样使用每秒 1 帧的兼容截图路径，桌面内置模式提供节目原生显示。

预览刷新与最终推流帧率分别控制。预监和设置页降到 1 FPS 后，OBS 的节目合成、HUD 输出、编码和音频沿用已应用的输出配置。输出状态中的 FPS 来自 OBS 合成统计；Windows 实际呈现率需要独立测量。

## 完成一场转播

1. **赛事准备**：启动软件后，使用顶部「赛事准备」进入赛事与素材。维护战队与选手，新增比赛、保存比赛，并在赛程中按住「载入」。载入后核对当前赛事和蓝红双方，进入下一步连接检查。
2. **连接检查**：在「连接与输出」的「数据 / 画面 / 声音 / 输出 / 包装 / 诊断与协作」选择任务。核对内置 OBS 状态、游戏合成快照、系统声音、解说麦克风和输出帧率，应用画面与音频。需要真实数据时连接对应客户端；使用回放时同时核对 Replay API。填写平台本次服务器与推流码并应用配置，完成后回到工作台。
3. **预监切入**：先点击场景卡，或在导播工作台按 `1–9` / `T` / `G` 选择预监。确认预监内容后，点击「切入节目」或按 `Enter`。节目大画面显示当前已切出的实际合成结果。推流和录制在工作台集中起停，以引擎返回的实际状态核对；平台接收与直播间上线仍在平台端确认。
4. **赛后收尾**：从「局间与收尾」依次核对胜方、终局数据、冻结报告、录像和下一步。系列赛局间按页面阻塞原因补齐资料，再进入下一局；整场结束时停止推流/录制并检查记录。报告准备与节目切入分步完成。

普通数字、字母及 Enter 只在导播工作台响应；Control+Enter 等配置组合键可跨页使用，输入框内屏蔽。常驻播出条提供跨页控制。编辑赛事、连接配置、BP、数据及使用指南时，数字、`T`、`G` 和 `Enter` 保留当前页面操作，避免误切节目。BP 页面原有明确的切入按钮继续可用。

## 验证范围

0.4.0 使用 [verify-production-workflow.mjs](../scripts/verify-production-workflow.mjs) 验证实际隔离 HTTP 服务与生产构建界面，15 项通过，包括同场景整体切入、输入保护、旧表单拒绝、长按新系列、素材清单、跨页 BP 草稿、多宽度布局、11 个输出场景和 4 类移动席位。执行 `npm run verify:production`，证据位于 `verification-output/production-0.4.0`。

桌面桥接与快照采用独立 fixture，13 组回归通过。

隔离检查脚本 [verify-director-workflow.mjs](../scripts/verify-director-workflow.mjs) 在随机本机端口创建新内存状态，模拟 OBS 状态与桌面桥接，并通过实际快照调度器发送固定测试像素。它核对 1920 × 1080、1440 × 900 和 1366 × 768 的三级布局、11 个场景卡、1 FPS 采样间隔、仅节目使用原生投影、页面切换释放、赛事新建与载入、工作台切入、跨页快捷键及收尾入口。模拟输出按钮仅修改 fixture 的内存状态。

```powershell
$env:RIFTCAST_PLAYWRIGHT_MODULE = 'C:\工具目录\node_modules\playwright\index.mjs'
node scripts/verify-director-workflow.mjs
```

脚本默认写入 `verification-output/workflow`，可通过 `RIFTCAST_WORKFLOW_VERIFY_DIR` 指定目录；本轮证据写入 `verification-output/frontend-0.4.0/director-workflow`。这些检查确认界面和请求行为；真实 OBS 原生窗口、实际屏幕帧率、游戏捕获和平台推流按各自现场条件验证。历史双路原生显示证据见 [原生预览性能](原生预览性能.md)。

2026 年 10 月 7 日的隔离检查通过，浏览器运行错误为 0。新建比赛、载入后进入连接页、应用接收地址并清空临时推流码、返回工作台起停模拟输出、断连后重置开播准备，以及赛后保存并打开记录页都完成闭环。快照订阅和原生桥接在离页或关页后释放；实际调度器的连续测试帧间隔不少于 970 毫秒。
