# 十分钟选手经济来源

导播工作台按系列、局号和队伍标识保存十分钟卡片。比赛第一次读取到 600–605 秒的数据时，系统冻结每位选手的姓名、英雄、KDA、补刀、可用的个人累计经济及六类经济来源。卡片记录实际采样秒数，可在之后通过经济来源场景调用；继续比赛、暂停、回放跳转和服务重启均保留已保存卡片。

首次连接时已超过 605 秒，会生成“未取得 10:00 时的数据”的卡片，其十分钟金额、KDA、补刀均为空。将回放跳回 600 秒前再播放跨越十分钟，可重新取得卡片。变更局号、系列或对阵队伍后，当前卡片与上一局隔离。

演示模式另行生成一份 10:00 的六类样例，每项标记 `demo`。样例的累计金额为该样例六类金额之和；当前演示比赛的十八分钟经济与这份十分钟样例分别保存。

保存比赛记录时，仅深拷当前局的十分钟卡片。记录创建后的比赛计时、演示变化、回放跳转及数据桥补值均不会改动已保存记录。JSON 导出包含该卡片；CSV 在原有比赛数据之后附加十分钟实际采样秒数、六类金额与各项来源。旧格式记录省略此部分仍可正常导出。

## 数据来源边界

Riot 官方 [Live Client Data API 文档](https://developer.riotgames.com/docs/lol#game-client-api_live-client-data-api) 与[官方完整响应样例](https://static.developer.riotgames.com/docs/lol/liveclientdata_sample.json)展示的 `playerlist`、`playerscores` 包含击杀、死亡、助攻、补刀、等级、装备、死亡状态及召唤师技能等字段。`activeplayer.currentGold` 表示当前选手持有的金币。公开接口未承诺提供所有选手的个人累计经济，也未提供击杀、小兵、野怪、防御塔、自增、其他这六类实际金币收益。

系统在对应字段缺失时显示“未提供”，保留 `null` 和来源 `unavailable`。补刀数与平均金币单价、击杀数与固定奖励的乘积不会用于生成六类精确金额。当前持有金币也不会被填入个人累计经济。

兼容赛事数据源可在 `allPlayers` 中提供以下扩展。它属于导播系统的兼容契约，标准 Riot Live Client 接口可省略它：

```json
{
  "riotId": "Player#TEAM",
  "totalGold": 4028,
  "goldSources": {
    "kills": 365,
    "minions": 1863,
    "monsters": 1,
    "towers": 280,
    "passive": 1213,
    "other": 306
  }
}
```

同样支持 `income` 代替 `goldSources`。类别键为 `kills`、`minions`、`monsters`、`towers`、`passive`、`other`，分别对应击杀、小兵、野怪、防御塔、自增、其他。每项必须为实际金币金额，范围为 0–1000000 的有限非负数；真实的 0 保留，空值、字符串、负值和非有限数拒收。仅收到部分分类时，其余分类保持空值。已有 `totalGold` 且分类金额之和超过它时，分类数据全部舍弃并保留已观察的累计金额。

## 本机赛事数据桥

具备精确金币分类的本机赛事数据源，可通过 `POST /api/player-income/telemetry` 补齐本局已生成的十分钟卡片。先读取 `GET /api/state` 中当前 `incomeSnapshots` 项，将其 `gameKey`、`capturedTime` 和 `playerId` 原样使用。只接受此前已采集到 600–605 秒的 `partial` 卡片；迟连错过十分钟的 `late` 卡片须先在回放中重新采集。

```json
{
  "gameKey": "从本局快照读取的完整 gameKey",
  "capturedTime": 600.5,
  "players": [
    {
      "playerId": "从本局快照读取的选手 playerId",
      "values": {
        "kills": 0,
        "minions": 1000,
        "monsters": 200,
        "towers": 160,
        "passive": 1213,
        "other": 500
      }
    }
  ]
}
```

`capturedTime` 必须与已有快照的实际采样时间完全相等，数据桥提供的金额必须来自该时刻保存的源数据。比赛后续进行到十一分钟时，仍可回填保存在桥中的十分钟源数据。已确认的金额保持冻结；数据桥只补齐空项，新项标记 `telemetry`。每次支持 1–10 名选手与部分分类；其余分类仍为空，所有已采选手的六项分类完整后卡片变为 `ready`。可选 `totalGold` 只用于填入此前缺失的十分钟个人累计经济。

局号或系列不匹配、时间戳不一致、未知或重复选手、错误类别、无效金额、改写已确认金额、分类合计超过累计金额均拒收。一次请求全部通过验证后才更新保存卡片。标准国服 Live Client API 未提供的六类金币数据，需要此类真实数据源才能自动补齐。

## 团战组件数据

游戏 API 提供的死亡状态、复活剩余时间、召唤师技能和装备槽位逐人保留。生命和资源值来自当前选手的 `championStats` 或兼容数据源提供的逐人 `championStats`；只有完整 Riot ID 或唯一一致的旧 summonerName 才能匹配 `activePlayer`。未匹配的其他选手保持生命、资源数值为空。

本次针对性测试覆盖十分钟跨越、一次冻结、迟连标记与回放补采、真实缺失值、兼容分类金额校验、重启保存、局与系列隔离、阵营对调，以及团战字段的逐人归属。
