[ensure-electron.cjs](../scripts/ensure-electron.cjs) 对现有 dist 只检查版本和 executable 存在；新下载经 npm Electron 包内 checksums 校验。它保留官方源失败后 npmmirror 重试路径，若需要本轮只用官方源，应在执行记录里固定和检查实际来源。不能把检查到版本号写成整个旧 dist 逐文件可信。

[ensure-obs.cjs](../scripts/ensure-obs.cjs) 检查归档大小/哈希，解压时检查路径、链接和展开上限；覆盖已有 runtime 前要求所有权 marker，保留 config 后替换，成功后会删除自己创建的旧 runtime 备份。正式构建使用独立新检出可避开操作员 runtime。marker 日常就绪检查覆盖三项核心 OBS 文件；音频构建另把 DLL/Lua 哈希加入 marker。完整原始运行时应结合固定归档和最终产物内容核验。

两份原生构建脚本在源码与产物哈希匹配时复用现有预编译文件；失配时会编译。投影 helper 重建还会执行新文件的 `self-test`。音频脚本需要时下载固定 OBS 源码、解出头文件、使用 gendef/dlltool 生成导入库，编译后复制自有 DLL/Lua 并更新独立 runtime marker。本轮只读哈希和 `node --check`，没有触发这些执行。

[electron-builder.cjs](../electron-builder.cjs) 的显式文件集合包含前端、服务 bundle、Electron 入口、必要 helper/OCR/native 文件与许可；extraResources 只取 OBS 的 bin/data/obs-plugins 及许可/marker、原始 VB-CABLE ZIP 和 `build/third-party`。不纳入项目 data、OBS config、录像、音乐或恢复文件。`afterPack` 要求各服务端外部依赖解析到包内 node_modules，加载 sharp 并确认包内原生 `.node`。最终仍须检查 ZIP 实际条目，尤其全取 `build/third-party` 的规则要求使用干净独立目录，避免旧文件混入。

正式脚本当前未自动拒绝脏工作区、已有同版本产物目录或已占用 tag；源码摘要使用 `git ls-files --cached --others --exclude-standard`，manifest 如实记录 HEAD、dirty 和源码文件哈希。父线程已选择未占用的 `0.8.0-rc.1`，对应使用说明为 [Windows-Release-0.8.0-rc.1.md](Windows-Release-0.8.0-rc.1.md)。须先提交获准版本与文档，在干净最终 SHA 构建，再核对 sourceRevision、workingTreeDirty=false、sourceDigest、安装包/ZIP 字节与 SHA256。构建不会发布 GitHub Release。

## 两份验收脚本的参数与副作用

以下命令是按当前源码整理的调用接口，本报告没有执行。

| 脚本 | 可用参数 | 实际行为和保存范围 |
| --- | --- | --- |
| `npm run verify:custom-scenes` | 无 CLI 参数；`RIFTCAST_PLAYWRIGHT_MODULE` 指定 Playwright 模块；`RIFTCAST_CHROMIUM_EXECUTABLE` 指定浏览器 | 在独立检出 `verification-output/custom-scenes/isolated-*` 内建立 service-data/engine-data/runtime。bin/data/obs-plugins 从当前检出 runtime **硬链接**过去。启动真实 OBS、可见 Chromium fixture 和另一个无头浏览器，枚举/捕获专用窗口，以实际 PNG 像素验证 PGM/PVW、TAKE、关闭窗口失败保护与保存/删除规则；不启动录制、虚拟摄像头或 RTMP |
| `npm run verify:release -- --executable <树外RiftCast.exe> --playwright <模块路径>` | `--executable` 或 `RIFTCAST_RELEASE_EXECUTABLE`；`--playwright` 或 `RIFTCAST_PLAYWRIGHT_MODULE`；无 skip-device/skip-record/dry-run | 未传 EXE 时复制本版本 win-unpacked 到系统临时目录；拒绝源码树内 EXE。在 `verification-output/release-<版本>/smoke-*` 建立合成 legacy-project、user-data；运行真实随包 Electron/OBS、原生投影、WAV 导入与播放/暂停、已注册摄像头复用、按设备条件执行伴侣音画或不可用分支，并在两分支均启动/停止本机录制；最后检验重复启动、正常退出与重启保留数据 |

custom 脚本通过子进程环境固定 service-data、external、禁自动连接/自启动及 offline；主进程另建 embedded engine。它没有覆盖继承的 `ENABLE_LAN`、`RIFTCAST_OBS_MODE` 或 `RIFTCAST_OBS_RUNTIME_DIR`。父进程 runtime 覆盖会优先于 engine 的 sandbox root，必须在运行前清空；父进程 OBS_MODE=external 也会使测试 engine 无法启动。须设置 ENABLE_LAN=0，并在子进程专用环境中隔离 APPDATA/LOCALAPPDATA/TEMP/TMP，不能在父会话永久改用户目录。

custom 的 finally 会先关闭两个浏览器、经 IPC 停止自建服务（5 秒后仅 kill 该 child）、关闭 owned OBS，再验证 sandbox 位于 evidence 下且名称以 isolated- 开头，递归删除该 sandbox。成功时还删除本 evidence 下旧 failure.json/failure.png/capture-diagnostics.log；会保留新 report 和截图。它删除的 custom 场景属于合成 service-data，上传图片保留断言在删除 sandbox 前执行。硬链接原始 runtime 文件应视为共享内容，测试不能改这些程序文件；config 是新建的独立目录。

release 脚本自行固定 `RIFTCAST_USER_DATA_DIR`、`RIFTCAST_IMPORT_FROM`、随机空闲端口、OBS_AUTOSTART=1、AUTO_CONNECT=0、OFFLINE=1，并删除继承的 RIFTCAST_DATA_DIR/OBS_RUNTIME_DIR/DEV 与 ELECTRON_RUN_AS_NODE。它仍继承 ENABLE_LAN、OBS_MODE、APPDATA、LOCALAPPDATA 和其他未覆盖变量。运行前应设置 ENABLE_LAN=0，去掉 OBS_MODE=external，给这次子进程准备独立 APPDATA/LOCALAPPDATA/TEMP/TMP；应用 userData 由脚本自己的 smoke 目录控制。外部传入 RIFTCAST_USER_DATA_DIR 会被脚本替换。

release 的迁移源完全由 createSeed、生成的图片/WAV 与 preserved fixture 构造，不读取真实项目 data。新 profile 的录制路径由 [obs-engine.ts](../server/obs-engine.ts) 设置为 `<smoke>/user-data/data/videos`；profile 已存在时该初始路径不会覆盖旧值，因此 fixture 源不能带真实 basic.ini。当前源只写 config/preserved.txt，不带 profile，符合该条件。脚本没有删除录像或 sandbox 的代码，结束后保留 fixture、录制与迁移证据。失败清理只停止本实例伴侣音画/录制并退出应用。

两个脚本都会触发 Windows 原生采集能力：custom 虽固定不存在的游戏窗口，仍创建默认桌面音频及默认麦克风来源；麦克风随后静音。release 未预置 obs-engine.json，默认空 gameWindow 会自动发现 LoL，默认桌面来源会采集当前系统输出，麦克风来源同样先创建再静音。目录隔离不能隔离这些设备副作用。若本轮要求只使用合成音画，需要在执行前做可审核的 fixture 采集配置修正，保留原行为断言，并交 Sol 验证；当前脚本没有通过 CLI 关闭这些来源的选项。

release 在进行摄像头测试前硬断言 driver.installed=true，再调用 `/api/obs/engine/virtual-camera/install`。[VirtualCameraDriver.install](../server/virtual-camera-driver.ts) 重新读取注册表，已有有效的 32/64 位注册会直接返回；未注册分支会 `RunAs` 执行 regsvr32。预检查与实际调用之间存在状态变化可能，当前脚本没有绝对阻止 UAC/注册的模式。未注册设备会导致当前脚本失败，不能把后续未执行项记为通过。

release 不调用 `/companion/prepare` 或 VB-CABLE install；已有音频 ready 时会启动真实 OBS Virtual Camera 和最终混音桥，通过 Electron 的隔离会话读取摄像头蓝/红 Program 帧及 PVW 隔离，再做录制独立停止和退出警告。音频不可用分支检查启动受拒且输出保持停止，再独立录制。它不设置 RTMP 凭据、不调用 start-stream，也不操作直播伴侣或真实直播间。报告始终把 companionAudioVerified、liveGameVerified、liveStreamVerified 保留为 false；真实观众接收继续单独列未运行。

## 安装隔离与保留数据

构建配置为 perMachine=false、allowElevation=false、asInvoker、runAfterFinish=false、deleteAppDataOnUninstall=false，安装与 ZIP 两种包均为 x64。已有 [install-local-release.ps1](../scripts/install-local-release.ps1) 只接受 `-SkipLaunch`：固定当前用户 Programs/RiftCast，直接 `/S` 安装，检查真实 Desktop 的“RiftCast 导播.lnk”；默认启动还把当前源码根设为 RIFTCAST_IMPORT_FROM。因此本阶段不得在现有账号上运行该 helper。

已核对锁定 electron-builder 26.15.3 的实际 NSIS 模板：

- `NsisTarget.js:157` 从固定 appId `cn.riftcast.director` 派生固定 GUID。`multiUser.nsh:26` 读取 HKCU 安装位置；`:50` 允许 `/D=` 改目标目录。APPDATA/LOCALAPPDATA 环境变量不会更换 HKCU 身份或应用 GUID。
- `installSection.nsh:52` 在安装文件前调用 uninstallOldVersion，`installUtil.nsh:224` 调用旧卸载器并保留 app data。指定新目录仍可能卸载同账号旧版本。
- 安装登记写入同一 GUID 的安装/卸载注册键，并创建固定名称开始菜单快捷方式；`--no-desktop-shortcut` 只抑制桌面快捷方式。模板没有对应运行时的 no-start-menu 参数。
- `/currentuser` 可选择当前用户模式。模板还处理已有 per-machine silent 升级并可能调用 UAC；仅看 allowElevation=false 不能代替对实际模板和已有登记的检查。

当前 HKCU 存在真实 RiftCast 0.5.0 登记，直接安装新 NSIS 会触碰既有安装边界。**在当前账号仅指定隔离目标目录无法满足“保留旧安装和快捷方式”的验收条件。** 原安装包完整验收应使用已有且获准的独立 Windows 用户或隔离机器；当前 Sandbox Disabled 且没有运行中的 hypervisor，不启用功能、不重启。另造不同 GUID 的测试安装包只能证明那个测试配置，不能直接作为正式包安装证明。正式构建和树外 ZIP 运行仍可继续；若最终仍无安装隔离环境，安装/升级/卸载项必须明确保留阻塞。

应用退出保留数据可在独立 fixture 目录核验：记录原 source state、uploads 和 config fixture 哈希，启动后保存 custom、退出并确认 owned service/OBS 消失，重启后确认保存项存在且原 source 未改；release 脚本还会在源目录写入一个新的合成标题，验证已存在目标数据不被再次导入覆盖。[release-runtime.cjs](../electron/release-runtime.cjs) 只在目标 data 不存在时复制显式 importFrom，拒绝导入链接；更新 owned runtime 时保留 config，并留下独立的 `.riftcast-obs-backup-*`。本轮尚未运行此验收。

安装后卸载留数据需要真实隔离安装环境：在该环境保存 fixture 数据、对源/目标哈希留证，再运行该环境自身卸载器，不传 `--delete-app-data`，检查应用文件/登记/该环境快捷方式变化及 fixture data/录像/config 保留。当前代码配置支持保留 app data，静态配置无法给出本轮卸载通过结论。
