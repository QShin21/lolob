# RiftCast 1.5.0 操作界面改版方案

基线：`origin/new`，RiftCast 1.4.2，提交 `dbeddea0a11631501658e10254ad47a3a6081fa5`。方案状态：首轮审查 UI-01～UI-11 已合并，可进入实施。目标版本：1.5.0。

本次把 RiftCast 的操作界面统一为一套专业广播工作台。视觉主线沿着“当前节目 → 下一次切入 → TAKE”展开；资料准备、数据核对、输出配置和赛后收尾共享相同的字体、间距、控件、状态与导航规则。交付范围包含 7 个主页面、15 个连接与输出任务、远程席位，以及它们打开的编辑器和弹窗。

PGM、PVW、待播保存、TAKE 请求、OBS 应用、人工核对继续采用现有状态与命令。界面主题作用于操作层；节目画布、风格包、监视画面、输出源和自定义场景内容沿用各自的播出配色。

## 一、成品视觉标准

成品采用石墨深色与浅瓷白两套完整主题，蓝色表达操作和选择，红色表达节目，绿色表达预监。主监看区、切入操作带、场景库与临场制作面板形成四块稳定的工作面。内容密集时保留清晰的间距和文字层级，空数据时给出简洁的下一步操作。

以下六项需要在改版前后的同尺寸截图中直接看见：

1. 导航、顶部信息、内容工作面和底部安全带有稳定的空间关系，顶部首次引导从整行横幅改为轻入口。
2. PGM/PVW 标题、场景名称、节目回执和 TAKE 构成连续的操作主线；TAKE 是导播台唯一高权重的红色实心操作。
3. 场景库使用规则的选择单元、完整的场景标题与状态标记；1366 × 768 首屏至少展示两整行场景。
4. 各页共享页头、分组面板、工具栏、页签和保存条；设置、管理、收尾与主导播台保持相同的视觉品质。
5. 深浅主题均有明确的前景、背景、边框和焦点状态；媒体内容保持原有画面。
6. 正文与操作文字达到清晰的字号，图标按钮具有完整热区；手机远程席位优先展示当前角色任务。

首轮证据目录为 `verification-output/ui-150/before/`，包含基线、授权控制席和补充子页面截图，以及 `metrics.json`、`contrast-samples.json`。该组截图来自隔离的暂停样本服务；初始截图内的权限禁用按样本状态解释，后续授权截图用于控制态复核。

## 三、设计变量与视觉规则

### 3.1 配色

保留 `--ui-*` 命名，所有操作组件通过语义变量取色。新增变量应覆盖选择、输入边界、按钮文字和状态背景，避免单个页面自行定义主题色。

| 变量/角色 | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| `--ui-bg` | `#0B1018` | `#F2F5FA` | 工作台底色 |
| `--ui-surface` | `#131B27` | `#FFFFFF` | 工作面、页头、侧栏 |
| `--ui-raised` | `#1B2635` | `#EDF2F8` | 次级控件与浮起容器 |
| `--ui-border` | `#334257` | `#B6C3D3` | 面板分隔与装饰边框 |
| `--ui-control-border` | `#60718A` | `#8595AA` | 输入和无填充按钮边界 |
| `--ui-text` | `#F3F6FB` | `#152438` | 正文与主数据 |
| `--ui-muted` | `#A7B6C9` | `#526379` | 辅助说明与元数据 |
| `--ui-accent` | `#8AB8FF` | `#245FC8` | 操作强调、链接、选择标记 |
| `--ui-on-accent` | `#0B1018` | `#FFFFFF` | 主按钮文字 |
| `--ui-hover` | `#243248` | `#E6EDF7` | 鼠标悬停 |
| `--ui-selected` | `#213758` | `#E1EDFF` | 当前选择背景 |
| `--ui-selection-border` | `#78AEF5` | `#376FC9` | 当前选择边界 |
| `--ui-focus` | `#A4CAFF` | `#175CD3` | 键盘焦点 |
| `--ui-pgm` | `#FF909B` | `#B42338` | PGM 标签、节目状态 |
| `--ui-pvw` | `#61D6AC` | `#116B4D` | PVW 标签、预监状态 |
| `--ui-take-bg` / `--ui-on-take` | `#BE2D43` / `#FFFFFF` | 同深色 | TAKE 操作 |
| `--ui-warning` | `#F6C66D` | `#986400` | 待处理、过期、保存冲突 |

状态背景分别用对应语义色的低饱和深底/浅底，文字仍取语义前景。蓝红队伍色、PGM/PVW 色、操作强调色各自独立。普通“本地实况”标记使用中性色，警告色留给需要处理的状态。

按上述色值计算：深色正文/面板对比度约 15.97:1，深色辅助文字约 8.39:1；浅色正文约 15.66:1，浅色辅助文字约 6.14:1；浅色主按钮白字约 5.92:1，TAKE 白字约 5.76:1。实现后以最终计算样式重新检查。

### 3.3 图标与按钮

全工作台继续使用 `lucide-react`。导航图标 20px，常规操作 16–18px，空状态 28–32px，线宽统一 1.8–2。收藏、排序、关闭、复制、刷新等操作使用对应 Lucide 图标，替换散落的 `★`、`☆`、`×`、箭头字符。图标与文字间距 6–8px；独立图标按钮始终有 `aria-label`。

按钮采用四级权重：主操作为蓝色实心；次操作为中性面板底与边框；辅助操作为文字/图标按钮；危险操作为语义红色描边或浅底。TAKE 独立采用红色实心。常规按钮高 36px，紧凑图标热区最小 32 × 32px，触控场景最小 44 × 44px。键盘焦点为清晰外描边。禁用项保留可读标签，并在附近呈现操作条件。

## 五、全局工作台与导播台布局

### 5.1 全局工作台

桌面采用稳定的导航栏、56px 顶栏、内容区和 56–64px 底部安全带。导航宽度在 1366px 为 72px，在 1920px 为 88px；每个入口有同规格图标与可见中文标签。当前页面通过底色、侧边标记和图标颜色共同提示。

顶栏保留品牌、当前节目比赛身份/比分、操作席位、同步状态和故障报告。比赛身份作为一个清晰的可点击对象，最小热区 36px。“首次设备引导”压为小型入口，完整步骤继续在现有对话框中打开，帮助页继续提供重新打开入口。

底部安全带持续展示 PGM/PVW、当前应用回执、输出状态和应急动作。导播台的 TAKE 位于切入操作带；其他页面保留底部 TAKE。连续的多个“待确认”状态合并为一组可展开的信号摘要，展开后仍逐项呈现 RTMP、摄像头、节目声音与 REC。危险动作与常规导航留出分隔。

### 5.2 导播台

保留当前 PGM 左、PVW 右的监视顺序与既有快捷键。双监视、切入操作带和场景库组成左侧主区；临场制作面板位于右侧。每块工作面都有完整边界与标题。

```text
┌ 阶段切换 · 本局时间 ─────────────────────── BP 与归属 / 本局资料 ┐
│ PGM · 当前节目             │ PVW · 下一次切入           │ 临场制作 │
│ 16:9 合成监视              │ 16:9 合成监视              │ 音频…    │
├ 节目回执 ───────────────── 下一次切入与变化 ─── TAKE ───┤ 任务正文 │
│ 场景库：搜索 · 阶段筛选 · 风格包 · 新建场景              │          │
│ 场景选择单元   场景选择单元   场景选择单元               │          │
│ 场景选择单元   场景选择单元   场景选择单元               │          │
└────────────────────────────────────────────────────────┴──────────┘
```

1366 × 768 的空间预算：顶栏 56px，底部安全带约 56px，内容上下留白合计 24–32px，页面工具栏 40px；主工作区约 560px。监视区含标题/页脚控制在 264–288px，切入带 72px，场景库保留至少 172px。监视画面始终等比缩放，在统一黑色监视槽内居中；原生投影窗口仍使用实际媒体节点边界。

场景库标题和工具栏最多两层，场景单元至少 54px。1366px 三列，1920px 四列，低宽两列/单列；搜索始终可用。场景名称 14px，说明和 PGM/PVW 徽标 12px；收藏和编辑有完整热区。列表内部滚动，最后一行文本和焦点边框都有底部留白。

右侧制作面板在 1366px 宽 320px，1920px 宽 392px。音频、回放、字幕、选手是四个常驻页签，更多任务使用可读列表入口。面板标题与操作影响说明在同一标题行；高频控制优先出现在顶部。音频页保留三通道横向推子和可读电平；通道设置按钮 32px，静音按钮 36px，音量显示 18px，说明至少 12px。采集设备与详细通道配置进入相邻设置入口。
