# 功能与接口

当前版本 0.4.0 的界面与操作变化见 [前端改进落地说明](前端改进落地-0.4.0.md)，业务规则见 [OB 全流程落地说明](OB全流程改进落地-0.3.0.md)；下表保留既有接口说明。

需求依据是三张功能清单截图和“Windows 国服，自定义比赛 / 本地观战”的使用场景。当前版本将本地可获取的数据、人工赛事资料、演示数据分别保留来源信息，便于导播在上播前核对。

选中选手后，表现榜场景显示底部中央焦点图层，留出游戏画面及右下小地图区域。预监用于确认接下来准备播出的场景，切出操作更新节目输出。工作台的预览背景帮助排版，局内及选手焦点 OBS 输出页保留透明背景。包装参考实际官方转播的布局与信息层级：[Worlds 2025 官方比赛录像](https://www.youtube.com/watch?v=sfVFGFfec64)、[2025 LPL 第三赛段 BLG 对 JDG 官方录像](https://www.bilibili.com/video/BV1vMYVzcEqv/?p=2)。

## 本地数据接入

| 来源 | 用途 | 官方说明与适用范围 |
| --- | --- | --- |
| LCU / League Client API | 读取客户端阶段和 BP | Riot 将其列为未正式支持第三方使用的本地服务，版本、文档和变更通知均无保证。[官方说明](https://developer.riotgames.com/docs/lol#league-client-api) |
| Live Client Data API，HTTPS 2999 | 局内名单、KDA、补刀、等级、装备、事件 | 官方文档描述为游戏运行期间的本地数据接口。全玩家结构缺少总经济 / XP；`activePlayer.currentGold` 仅属于当前玩家的可用金币。[接口说明](https://developer.riotgames.com/docs/lol#live-client-data-api) |
| Replay API，HTTPS 2999 | 本机回放播放控制 | 默认关闭，需在配置中启用；适用回放制作。[Riot 的 League Director 示例](https://github.com/RiotGames/leaguedirector) |
| Data Dragon | 英雄、装备静态数据与图片 | 官方静态资源，更新可能落后于客户端；装备名称、图片和购买价使用同一静态目录版本，静态购买价与个人累计经济分别展示。[资源说明](https://developer.riotgames.com/docs/lol#data-dragon) |
| 观战经济数据桥 | 团队经济、经济差、曲线与个人累计金币 | 对可见且无遮挡的顶部经济区域和底部个人金币列进行 Windows OCR。个人 `current(total)` 通过同侧 KDA + 补刀唯一匹配 API 名单；累计金币与余额分开，10 秒有效。个人 XP 仍依赖可用字段。见 [实时预览与个人经济](实时预览与个人经济.md) |
| Riot 云 API | 待扩展的历史数据 | 官方公开平台路由表没有 CN；首版国服历史数据使用本机记录与人工资料。[路由表](https://support-developer.riotgames.com/hc/en-us/articles/22698698001939-League-of-Legends#routing-values) |
| OBS WebSocket | 查询和切换本地 OBS 场景、添加 HUD、应用自定义 RTMP 配置和查询推流状态 | 按 OBS 内已配置的 WebSocket 服务器地址、密码连接。配置使用 `SetStreamServiceSettings`，状态使用 `GetStreamStatus`。[官方协议](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md) |

本地服务读取 API 并统一发送给工作台及 OBS 输出页。浏览器侧无需知道 LCU 的临时密码。切入真实模式或重启真实服务会清除旧局采样；接口不支持的字段保留为空。运行中连接中断时，选手与事件保留最后成功采样，HUD 标注中断和数据截至时间。团队经济仍按独立的 10 秒有效期处理，超时显示 `—`。

连接 LCU 时，在设置中填写当前 `LeagueClient` 的 `lockfile` 路径。国服安装目录可能随 WeGame 配置变化，请从实际安装目录选择。该文件包含本地端口和临时凭据，客户端重启后需要重新读取。选择 BP 同步前确认所用客户端实际能获取此次自定义选人流程。

大厅尚未创建对局时，`/lol-gameflow/v1/session` 可以返回 404。服务会继续检查 `/lol-gameflow/v1/gameflow-phase`；有效的 `None` / `Lobby` 阶段保持已连接并显示“等待 BP”。进入选人但暂时缺少可确认的蓝红方信息时，等待真实阵容数据，认证失败等其他错误仍按连接失败处理。

Live Client 使用 `https://127.0.0.1:2999/liveclientdata/allgamedata`。游戏尚未运行时连接失败属于正常状态。API 的可用字段以本机 Swagger 和实际返回为准，在正式比赛前先用一场自定义比赛完整演练。[本机 API 规范](https://127.0.0.1:2999/swagger/v3/openapi.json)

## 回放与经济的实机接入

本机回放的 HTTP 404 已定位到未启用配置开关。实际配置为 `E:\WeGameApps\英雄联盟\Game\Config\game.cfg`；修改前备份为 `game.cfg.riftcast-backup-20261004001148`。在 `[General]` 节设置以下值，用户重开录像后 `/replay/playback` 返回 HTTP 200，回放诊断为 `ready`：

```ini
[General]
EnableReplayApi=1
```

在其他安装中，先退出回放并备份该安装的配置，在已有的 `[General]` 节修改开关，随后重新打开回放。在“连接与输出 → 回放接口诊断”点击“重新检测”，按实际路径、HTTP 状态及重启提示处理。启动脚本保留游戏配置。详细步骤、备份位置和观战经济校准见 [回放与经济](回放与经济.md)；回放开关依据 [Riot 官方 League Director 使用说明](https://github.com/RiotGames/leaguedirector#frequently-asked-questions)。

回放控件的操作结果来自本机 Replay API。读取就绪状态已经实测，正式制作时仍应逐项确认暂停、倍速和跳转的画面效果。当前未实现自动跟随激烈战斗、3D 运镜轨道或远程回放录制管线。

经济数据桥只在真实数据模式使用。OCR 默认关闭，点击“自动定位经济区域（3秒）”并显示游戏顶部扫描带，可以寻找唯一的一对经济金额；确认成功后保存区域并启用识别，歧义或跨比赛的结果会被拒绝。手动区域字段填写游戏客户区的百分比，接口使用对应 `0–1` 坐标；区域限定在顶部、互不重叠。点击“保存识别区域”后，可通过“3 秒后读取一次”留出调整窗口位置的时间。游戏窗口未最小化、取样区域完整可见且无遮挡时，后台及双屏布局也可读取。人工校准允许 `23400`、`23,400`、`23.4k`、`2.34万` 等可确认文字，提交按钮为“校准并更新经济”。数据优先级为 `api → manual → ocr`，每次样本有效期为 10 秒。画面显示精度与原文会保留，缺少有效数据时停止追加经济曲线点。

## 制作与数据保存

工作流按“赛前资料 → 预览 / 切出 → BP → 局内 → 赛后 → 保存记录”组织。自动阶段识别用于更新工作台阶段；导播仍需主动确认节目场景，避免误切。

上传素材与持久化数据保存在项目 `data` 目录。比赛记录用于保存已采集的选手统计、事件、经济曲线和当前经济来源状态。JSON 导出当前数据及已保存记录都会包含可用的 `economyFeed`，曲线中的实际采样点包含 `source`。CSV 分为选手统计、团队累计经济 / 来源、经济曲线 / 采样来源三组；个人累计经济缺失时保留缺失值，团队 OCR / 人工经济不会分摊到个人。它们不包含游戏画面，视频需要 OBS 录制。

设备协作访问同一个服务，因此多个设备的场景操作会影响同一节目。首版没有角色权限、操作排队、团队云同步或商业登录额度。开启 LAN 前关闭旧服务；开启后使用设置里提供的凭证地址，在同一现场网络访问。

## 项目服务接口

控制服务默认地址为 `http://127.0.0.1:3888`。以下接口属于本项目，便于后续接入触控面板或数据处理脚本：

| 接口 | 用途 |
| --- | --- |
| `GET /api/health` | 服务健康与项目标识，桌面窗口据此确认可复用的服务 |
| `GET /api/state` | 当前导播状态 |
| `POST /api/action` | 发送场景、比赛资料、HUD 和记录操作 |
| `GET /api/network` | 本机查询协作地址与控制凭证 |
| `GET /api/champions` | 官方英雄静态资料与资源地址 |
| `GET /api/export?format=json\|csv` | 导出当前数据；传 `recordingId` 可导出指定已保存记录 |
| `POST /api/replay` | `{ paused?, speed?, time? }`，操作本机回放 |
| `GET /api/replay/diagnostics` | 检查 Replay、Swagger、配置开关及重开条件，返回就绪状态和具体原因 |
| `GET /api/economy/status` | 当前团队经济、`source` / `status`、采样 / 失效时间及可用原文 |
| `POST /api/economy/config` | 仅本机：`{ enabled, blue: { x,y,width,height }, red: { x,y,width,height } }`，区域使用 `0–1` 坐标 |
| `POST /api/economy/sample` | 仅本机：`{ blue, red }`，双方观战比分板数字或文字，立即校准经济 |
| `POST /api/economy/probe` | 仅本机：`{ delayMs? }`，延迟 `0–5000` 毫秒后读取可见且无遮挡的游戏区域 |
| `POST /api/economy/calibrate` | 仅本机：`{ delayMs? }`，默认延迟 3000 毫秒，自动定位并保存区域、启用识别，返回 `{ config, feed }` |
| `POST /api/connect` | 请求连接 LCU、Live、Replay 或 OBS |
| `GET /api/obs/scenes` | 查询 OBS 场景及当前场景 |
| `POST /api/obs/scene` | `{ sceneName }`，切换已存在的 OBS 场景 |
| `GET /api/obs/stream/status` | 查询 OBS 推流、重连、时长和丢帧白名单字段；远端遵循一般读取接口鉴权 |
| `POST /api/obs/stream/settings` | 仅本机：`{ server, key }`，应用 OBS 自定义 RTMP 配置；推流中拒绝修改 |
| `POST /api/obs/hud` | 仅本机：`{ sceneName }`，向指定 OBS 场景添加 RiftCast 1920 × 1080 浏览器来源 |
| `GET /api/obs/engine` | 仅本机：引擎模式、进程/连接、推流/录制状态、来源、设备候选和已应用选择 |
| `POST /api/obs/engine/start` | 仅本机：启动独立便携 OBS，自动初始化画布、场景、HUD、游戏捕获和音频 |
| `POST /api/obs/engine/mode` | 仅本机：`{ mode: "embedded" \| "external" }`；正在输出时拒绝切换 |
| `POST /api/obs/engine/setup` | 仅本机：`{ gameWindow?, desktopDevice?, micDevice?, micEnabled? }`；停止输出后调整来源 |
| `GET /api/obs/engine/preview` | 仅本机：当前节目场景 JPEG 合成截图，960 × 540，供工作台每 2 秒预览 |
| `POST /api/obs/engine/output` | 仅本机：`{ action: "start-stream" \| "stop-stream" \| "start-record" \| "stop-record" }` |
| `GET /overlay` | OBS 节目输出页 |
| `GET /remote?token=…` | 手机遥控页 |
| `WS /ws` | 状态同步；远端使用 `?token=…` |

远端写操作通过 `X-Control-Token` 请求头或 `token` 查询参数鉴权，控制凭证只在本机 `/api/network` 返回。局域网服务需 `ENABLE_LAN=1` 显式开启。第一版按现场所有控制设备共享权限设计，后续可以增加观察席、字幕席和导播席权限。

经济区域配置、自动定位、人工采样和 OCR 请求这四项写操作仅允许在导播主机调用。OBS 推流配置与 HUD 安装两项写操作同样仅允许本机调用，即使开启 LAN 并持有协作凭证，远端也无法执行。推流状态只返回白名单字段，远端请求遵循一般读取接口鉴权。项目不提供读取当前推流配置的 GET 接口，推流码不进入项目状态与导出。应用配置会交给 OBS 保存，保留当前节目场景；HUD 添加同样保留当前场景，游戏捕获和音频仍需在 OBS 配置。具体直播姬链路、用户截图样例和平台状态确认步骤见 [Bilibili 直播姬接入](Bilibili直播姬.md)。

后续可按真实比赛验证结果补充：客户端版本兼容配置、赛事历史数据导入、PB% 和英雄池统计、完整符文树、摄像编排、基于 OBS 的场景映射、Replay 运镜、经过验证的概率模型。参考清单中的专有引擎名称没有在本项目中作为已接入能力使用。
