# RiftCast 0.8.0-rc.2 Windows 候选版

2026-10-15。本候选版整合本轮导播工作台、十一种节目包装、自定义场景和五席协作的重构，以及 live / BP 小播放器文字修正。抖音伴侣继续使用 OBS Virtual Camera 发送 Program 视频、通过基础版 VB-CABLE 接收最终节目混音。

RC2 在 RC1 基础上增加本轮原生验收保护与隔离留证，产品权限、服务接口及依赖锁定值保持。RC1 的安装包、ZIP 与历史说明保留；本版本使用独立文件名与最终源码提交，不覆盖 RC1 资产。

**这是 Windows 候选版。当前仍待正式产物核验、隔离安装/升级/卸载，以及真实原生预览和音画验证，尚无稳定版验收结论。** 源码和版本以本包的 `release-manifest.json` 为准；最终 `sourceRevision` 指向生成该包的提交，不能使用此前 e3828b8 的测试基线或旧包哈希代替。

## 双击运行

构建目录为 `release/0.8.0-rc.2/`，文件名如下。只在取得完整产物并核对同目录 `SHA256SUMS.txt` 后运行。

| 形式 | 文件 | 操作 |
| --- | --- | --- |
| 安装版 | `RiftCast-0.8.0-rc.2-Setup-x64.exe` | 双击安装程序，选择当前用户的可写安装位置；完成后双击桌面“RiftCast 导播”快捷方式 |
| 免安装版 | `RiftCast-0.8.0-rc.2-Windows-x64.zip` | 完整解压到普通可写目录，双击其中 `RiftCast.exe`；保留 resources 和其余随包文件，不在 ZIP 中直接运行 |

需要 64 位 Windows。运行时随包提供，无需另装 Node.js、Electron 或 OBS。首次启动会从随包文件复制独立 OBS 运行时到用户数据目录并启动引擎；启动进度和失败信息写入用户日志。安装过程不会自动启动应用，普通首次启动不会安装摄像头或音频驱动，也不会自动开播或录制。

已有 RiftCast 安装时，Setup 按同一应用身份执行升级流程；指定另一安装目录仍可能替换原安装及快捷方式。本轮缺少独立 Windows 用户/机器的安装验收条件。评估候选版应先退出原应用并备份用户数据，选择隔离环境；ZIP 默认也会使用同一用户数据目录。

## 数据、退出与迁移

安装版和 ZIP 默认共用 `%APPDATA%\RiftCast`，目录用途如下。

| 位置 | 内容 |
| --- | --- |
| `data` | 赛事、队伍、选手、上传素材、已保存比赛记录与设置 |
| `data\videos` | 新建内置 OBS 配置的默认录制目录，默认 MKV；既有 OBS profile 的录制路径会继续保留 |
| `runtime\obs-studio\config` | RiftCast 自有 OBS 配置及恢复资料 |
| `logs\director.log` | 桌面与自有服务启动日志 |
| `migration.json` | 使用显式旧项目导入时的迁移记录 |

退出时先停止需要结束的输出。活动输出或录制会触发确认；正常退出保存赛事状态并关闭本应用启动的服务与 OBS。赛事、素材、音乐、录像和恢复资料继续保留。安装配置要求升级和卸载保留 app data，本候选版的实际升级/卸载保留行为仍待隔离验收。

备份时先完全退出应用，再复制整个 `%APPDATA%\RiftCast`。通用包不包含操作者赛事、录像、音乐、推流码或 OBS 密码。首次使用创建新的本地数据；迁移旧源码项目只在显式指定来源且目标 data 不存在时复制，原文件保留，已有目标数据不会被后续源目录变化覆盖。不要把真实项目目录用于自动验收 fixture。

## 输出与设备准备

1. 打开「连接与输出 → 画面 / 声音」，核对内置引擎、游戏画面、系统声音和解说设备。默认解说麦克风静音；来源修改需显式应用。
2. 在「输出」查看「抖音直播伴侣」或「RTMP 推流」，点击「设为下一次输出」应用目标。仅查看路径不会更改引擎目标。
3. 本轮候选评估仅复用已注册的 OBS Virtual Camera 和可用的基础版 VB-CABLE。设备未就绪时展开「设备准备与恢复」读取具体原因并停止该项验收。不要点击「准备完整音画设备」或「仅准备虚拟摄像头」；它们仍是产品中可能安装或注册组件的显式操作，属于本轮禁止范围。
4. 在导播台核对 PVW 和正式 PGM，按需要 TAKE；点击「启动伴侣音画」后，在直播伴侣选择摄像头 **OBS Virtual Camera**、麦克风 **CABLE Output (VB-Audio Virtual Cable)**。关闭伴侣额外系统声、原麦克风和重复监听，核对画面、电平及口型。
5. 直播间的开播与关播由直播伴侣完成。收尾先结束直播间，再按住停止 RiftCast 的伴侣音画。本机录制通过「开始本机录制 / 停止本机录制」独立控制。

Program 最终音轨 1 以 48 kHz 双声道送入 CABLE Input，伴侣从 CABLE Output 接收；虚拟摄像头只承载画面。RTMP 路径需要应用当次服务器与推流码，再显式启动推流。软件回执、设备枚举、电平和本地录像都不能单独证明直播间或观众接收正常。

用户授权原文为“允许隔离原生验收；禁止驱动安装、注册、UAC、重启和真实推流。”本轮只使用隔离 fixture 和现有注册设备；缺失设备应如实记为失败或阻塞，不能安装后补测或跳过后称通过。禁止运行 NSIS 和改动真实 OBS 配置。本轮也不操作直播伴侣开播或真实平台。

开发验收命令为 `npm run verify:custom-scenes` 以及 `npm run verify:release -- --reuse-drivers-only --executable <树外RiftCast.exe> --playwright <模块路径>`。先由 Sol 审核 guard，再从本版本干净提交和正式产物执行。两脚本固定本机监听和独立 APPDATA/LOCALAPPDATA/TEMP/TMP，并拦截准备/安装/注册和 start-stream 请求；release 读取既有设备状态前后对照，录制前核对 OBS 实际目录为 fixture 的 `user-data/data/videos`。本轮不使用 release 的旧无标记准备分支。每次 custom evidence、OBS fixture 配置、诊断和 release fixture 录像均保留。默认桌面音频、已静音麦克风与专用窗口捕获属于获准的设备使用范围，目录隔离不会隔离物理设备。

## 音乐与恢复

「连接与输出 → 声音」可导入 32 MB 以内的 MP3、WAV、OGG 或 FLAC。新音乐默认暂停、静音、-18 dB，播放、暂停、停止与静音分别控制。更换音乐文件需要先停止伴侣输出、RTMP 和录制。

音乐加入正式节目混音，PVW 不重复加入音乐。原声回放播放片段声音并临时关闭现场游戏和解说；新解说回放关闭片段原声并保留现场解说，音乐继续参与。返回比赛恢复切入前状态；停止伴侣混音会恢复其托管的监听、音轨和端点状态。恢复失败时保留错误和恢复文件，核对实际声音后再继续。

## 产物、签名与许可

正式入口保持 `npm run release:win`，只在干净的最终 Windows x64 检出执行；同目录的 `release-manifest.json` 记录源码提交、源码摘要和产物 SHA-256，`SHA256SUMS.txt` 用于核对 Setup/ZIP。包内另有 manifest。当前文档不预填尚未生成的产物哈希。

本候选版尚无已签名产物结论，项目未配置 Windows 商业代码签名证书。已下载官方 Electron 44.5.1 ZIP 的 SHA-256 核验通过，解出的 Electron EXE 的 `Get-AuthenticodeSignature` 为 **NotSigned**。最终 RiftCast 安装包和应用 EXE 仍应逐项记录实际签名状态；文件哈希与数字签名各自说明不同事实。

随包包括官方 OBS Studio 32.2.2、对应完整源码、GPL 文本、音频桥接组件源码和构建说明，以及未经修改的基础版 VB-CABLE Pack45 ZIP 和来源许可说明。许可材料在应用 `resources/licenses`，VB-CABLE 原归档在 `resources/vbcable`。`THIRD_PARTY_OBS.md`、`THIRD_PARTY_AUDIO.md` 与源码/许可证均保留。

VB-CABLE 来自 [VB-Audio Software](https://vb-audio.com/Cable/)，采用 donationware 模式；专业使用和批量分发应按 [官方许可说明](https://vb-audio.com/Services/licensing.htm) 办理。包中不含 A+B、C+D。
