# 1.7.0 团队协作维护说明

团队通道使用独立的 WebSocket 监听器，默认 TCP 3890；工作台 API 继续使用原有本地服务。协作者的本地服务主动连接主控端，预览、请求和视角回传共用该连接。监听器支持 IPv4 和 IPv6，不向公网开放 OBS、Riot 客户端或工作台维护 API。

每次建立会话生成 192 位随机配对码，通过 HMAC 挑战验证建立连接。后续记录使用 AES-256-GCM，双向独立随机 nonce 前缀和递增序列；修改、重放及乱序记录会被拒绝。配对信息保留在进程内，结束或重建会话后原码失效。

视频由用户明确选择的桌面窗口采集，经 VP8 WebM 传输，声音可选 Opus 系统回环。Electron 授权同时核对主窗口、来源和一次性窗口选择；兼容运行时以 media 权限报告桌面采集的路径，授权时间受本次选择约束。接收端使用 MediaSource 连续解码；缓存和积压有上限，迟加入者可请求发送者重新建立编码。

主控端把远端视频作为本机 OBS 浏览器来源。切入前等待该来源报告实际解码；失败时恢复此前来源设置。游戏模式在主控包装下显示；完整节目模式覆盖主控包装。携带远端声音时临时静音主控桌面总线，恢复主控来源时还原。OBS 来源保留恢复标记，重启配置时撤下旧协作来源并恢复声音，避免中断会话残留黑画面。

默认切换请求由主控端批准。自动批准由建组设置明确启用。请求经统一的动作队列应用；回执区分待批准、已应用、拒绝和失败。远端媒体停止或超过时限未收到数据时尝试恢复主控来源；恢复失败保持提示，并在后续检查重试。

验证入口：

- `node --import tsx --test server/collaboration.test.ts server/obs-collaboration.test.ts server/obs-engine.test.ts`：配对、加密、双向传输、IPv6、审批、错误回执、回退、声画策略及重启恢复。
- `node scripts/verify-collaboration-170.mjs`：两个独立数据目录中的浏览器视频与控制流程。
- `node scripts/verify-collaboration-170.mjs --obs`：独立复制的真实 OBS、远端视频与 Opus、节目切入、本地录制和回退。
- `node scripts/verify-capture-170.mjs`：真实 Electron IPC、指定测试窗口的连续采集与系统声音轨。使用自建测试窗口，隔离用户目录。

浏览器脚本通过 `RIFTCAST_PLAYWRIGHT_MODULE` 读取 Playwright。实际跨公网路由、真实 LoL 窗口及直播平台接收需要在对应环境核对。
