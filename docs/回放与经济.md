# 回放连接与观战经济

0.4.0 继续保护正在播出的 Riot 游戏来源，暂停、跳转与倍速写入会被拒绝。直播精彩回放使用 OBS 独立缓冲片段，在工作台「回放」任务完成保存、入出点、预监、切入与立即返回比赛；界面变化见 [0.4.0 落地说明](前端改进落地-0.4.0.md)，业务及声音策略见 [0.3.0 流程说明](OB全流程改进落地-0.3.0.md)。以下 Replay 写入步骤适用于明确的离线录像制作。

适用环境：Windows 国服、本机自定义比赛观战与录像回放。以下步骤使用 RiftCast 的“连接与输出”页面；导播工作台与运行游戏的电脑应连接同一个本地服务。

## 回放接口 404 的排查

游戏配置未启用 Replay API 时，回放接口可能返回 HTTP 404。先在连接与输出页面查看诊断；备份游戏配置，再确认 General 节的 EnableReplayApi=1，随后重新打开录像。暂停、倍速与跳转需要在制作使用的录像中核对。

## 接入另一台电脑的回放

1. 在“连接与输出 → 数据 → 本机客户端”填写实际的“英雄联盟安装目录”，保存设置。运行中的游戏进程也可帮助服务定位当前安装位置。
2. 退出当前录像回放，备份该安装目录的 `Game/Config/game.cfg` 或 `Config/game.cfg`。在已有的 `[General]` 节加入或修改以下开关，保持该节唯一。

   ```ini
   [General]
   EnableReplayApi=1
   ```

3. 保存后重新打开录像，等待加载完成。正在运行的游戏进程需要重新读取配置。
4. 打开“连接与输出 → 诊断 / 协作 → 回放接口诊断”，点击“重新检测”。诊断会显示配置路径、开关状态、本机 2999 端口及 Replay / Swagger 路径的读取结果。
5. 诊断显示“回放 API 已就绪”后，在 Replay API 连接卡点击“连接服务”或“重新连接”，再使用“回放控制”中的“暂停回放 / 继续播放”“应用倍速”和按秒数“跳转”。

| 诊断状态 | 处理方式 |
| --- | --- |
| `ready` | `/replay/playback` 返回兼容的播放状态，可以连接并操作回放 |
| `disabled` | 配置尚未启用；备份并修改开关，随后重新打开回放 |
| `restart-required` | 配置已修改，当前游戏进程早于修改启动；重新打开回放 |
| `not-running` | 本机游戏接口未启动；先打开录像并等待加载 |
| `unsupported` | 路径返回 404，当前进程尚未提供接口；重开后继续失败时核对客户端版本 |
| `unavailable` / `invalid-response` | 接口超时、暂不可用或播放状态格式不兼容；检查具体诊断提示 |

回放控制只改变录像的播放状态。LCU 与 Live Client 负责其他阶段及局内统计，两者的连接成功状态应分别检查。启用方法依据 [Riot 官方 League Director 说明](https://github.com/RiotGames/leaguedirector#frequently-asked-questions)。

## 团队经济的数据口径

本机已读取 10 名玩家的 Live Client 返回值，并检查当前 Swagger。现有全玩家公开字段提供 KDA、补刀、等级、装备等信息，缺少每名选手的累计经济和 XP。`activePlayer.currentGold` 是当前玩家的可用金币；装备静态购买价可用于装备价值分析。

团队经济数据桥从可见观战比分板获取蓝红双方经济，用于团队比分、经济差和曲线。支持以下来源，界面和保存的记录保留对应来源信息。

| 来源 | 口径与优先级 |
| --- | --- |
| `api` | 接入字段实际提供双方累计经济时优先使用 |
| `manual` | 人工录入观战比分板上的双方经济；在有效期内优先于 OCR |
| `ocr` | Windows 识别可见观战窗口中已校准、未被其他窗口遮挡的蓝红经济数字区域 |
| `none` | 没有有效采样；团队经济显示 `—`，不生成新的经济曲线点 |

各来源样本的有效期为 **10 秒**。超时后状态变为 `stale`，团队经济清空；下一次有效采样可恢复显示。切换模式、比赛身份或局数会清除当前采样；录像时间明显回退或跳转时也会清除，随后重新读取。历史曲线保存已经取得的样本，读取中断期间不补造数据点。

比分板显示 `23.4k` 时，程序按 `23400` 存储并保留原始识别文字，精度对应画面显示。个人累计经济另从底部金币列 `current(total)` 的括号内精确整数读取，通过同侧 KDA 和补刀匹配 API 名单；余额独立保存，个人 XP 继续保持缺失状态。设置与验证见 [实时预览与个人经济](实时预览与个人经济.md)。

## 使用 Windows OCR

1. 切换“数据来源”为“客户端实时”，连接 Live Client，并打开本机观战或录像，使原始游戏的团队经济数字可见。
2. 展开“团队与个人经济来源”。该入口位于“连接与输出”和“实时数据”。首次使用点击“自动定位经济区域（3秒）”，随后立即切回游戏，保持原生顶部观战计分条与顶部扫描带完整可见。个人识别同时需要底部原生计分板的金币、KDA 和补刀列可见。
3. 自动定位会寻找顶部画面中唯一的一对 `k` / `万` 格式经济金额，确认蓝方在左、红方在右。定位成功后保存两方区域、启用持续识别，并取得首个 OCR 样本。切回工作台核对“识别文本”、双方数值和区域示意。
4. 定位未能确认唯一金额时，原有区域配置保持不变。此时手工为两方填写区域：只框住经济数字，避开队标、击杀、计时与相邻文字，然后打开“启用观战经济识别”并点击“保存识别区域”。
5. 工作台字段使用相对于游戏**客户区**的百分比：“左 %”“上 %”为左上角位置，“宽 %”“高 %”为区域宽高。例如横坐标位于画面宽度的 33% 时，在“左 %”输入 `33`。边框和桌面分辨率不计入区域。两个区域应完全处于游戏画面的上半部分，并且互不重叠。接口及持久化配置将百分比转换为 `0–1` 坐标。
6. 点击“3 秒后读取一次”后确保游戏窗口未最小化、两方经济区域完整可见且无遮挡；请求会等待 3 秒后尝试识别。启用后服务也会自动尝试读取。逐方核对读数与原始比分板；识别错误时调整区域并保存。正式上播前先确认数值、队伍对应关系和画面分辨率。

识别使用 Windows 10 / 11 自带的 OCR 组件，默认关闭。窗口至少为 640 × 360；每个识别区域至少为 8 × 8 像素，且需完整位于可见屏幕。自动识别约每 2 秒尝试一次，单次任务结束后才会继续。游戏窗口可以留在另一块屏幕或后台，只要取样区域完整可见且未被其他窗口遮挡，导播操作控制台时仍可持续读取。

采集前后会检查窗口可见性及区域遮挡。窗口最小化、取样区域被覆盖或 OCR 语言组件不可用时会停止本次读取并显示原因；最后的有效样本仍受 10 秒有效期限制。区域混入游戏内其他文字可能导致读数错误，应按原始经济数字重新校准。

自动定位扫描游戏客户区顶部 12%、横向 20%–80% 的中央区域，需要该扫描区域无遮挡，接受可明确识别的 `k` / `万` 金额。计时、没有单位的纯数字、第三个候选金额或无法确认左右队伍位置时会拒绝保存定位结果，可以改用手动区域。自动定位过程中比赛或录像位置发生跳转时，本次定位结果会被丢弃。完成定位后的持续读取只需要已保存的两块区域无遮挡。

本机已在 3840 × 2160 的实际游戏画面中成功定位并读取蓝方 `19.8k`、红方 `22.2k`，确认两方区域约为 `x=0.4166 / 0.5751`、`y=0.0145`、宽 `0.0296`、高 `0.0215`。这些坐标记录本次画面，其他分辨率或 HUD 布局应重新定位。实际 Windows OCR 对该画面的小数点曾返回 `·`，解析器仅在相邻数字之间兼容该字符。

保存区域后的读取优先使用英语数字识别，并在可用时用 Windows 用户语言重读；两个合法结果矛盾时拒绝本次样本，字母 `l` 不转换成数字 `1`。4K 自动定位已有真实画面验证；加入语言复核后的连续区域读取稳定性仍需下一场实际观战核对。

上述实际 ROI 已通过本机 3888 服务确认并保存，识别开关为 `enabled=true`。保存后本次游戏退出，2999 游戏端口未监听，当前没有新的实时经济样本。再次打开观战或回放后保持区域可见，程序才能继续读取；更换布局时先重新定位。

如 Windows 提示 OCR 语言组件不可用，在系统语言设置中为中文或英语安装文字识别组件。手动区域模式在内存中裁剪两个区域，自动定位读取顶部带进行文字与位置识别；当前实现不会将识别图片写入项目素材目录。

## 人工校准

暂时无法使用 OCR 时，在“人工校准双方经济”中按观战比分板输入蓝红双方数值，点击“校准并更新经济”。支持整数、带千位分隔符的整数、`k` / `K` 和“万”，例如 `23400`、`23,400`、`23.4k`、`2.34万`。两方都需要可确认的完整数字，允许范围为 `0–1000000`。

人工校准同样在 10 秒后失效，需要重新提交当时的可见比分板数值。若 OCR 已启用，人工样本失效后可以使用仍在有效期内的 OCR 结果。人工校准不填充个人金币、XP、实时胜率或未读取的资源计时。

## 本项目的经济接口

默认服务地址为 `http://127.0.0.1:3888`。以下路径属于 RiftCast 本地服务：

| 接口 | 请求与结果 |
| --- | --- |
| `GET /api/economy/status` | 当前 `source`、`status`、蓝红数值、采样时间、失效时间及可用的原文 |
| `POST /api/economy/config` | `{ enabled, blue: { x, y, width, height }, red: { x, y, width, height } }`；接口坐标为 `0–1`，界面百分比需除以 100 |
| `POST /api/economy/sample` | `{ blue, red }`；两方为可解析数字或字符串，立即校准团队经济 |
| `POST /api/economy/probe` | `{ delayMs?: number }`；允许 `0–5000` 的整数，延时结束后读取可见且无遮挡的游戏区域 |
| `POST /api/economy/calibrate` | `{ delayMs?: number }`；默认等待 3000 毫秒，允许 `0–5000`，自动定位并保存区域、启用识别，返回 `{ config, feed }` |

四个经济写接口仅允许导播主机的回环请求。远端设备可以查看同步的团队读数，区域配置、自动定位、手工采样及截图识别请求在导播主机操作。

## 录像与 OBS 的配合

OBS 游戏捕获提供真实游戏画面；RiftCast 浏览器来源提供包装与数据。叠加 HUD 可能遮住原始经济数字，校准时请确认 OCR 识别的是游戏窗口中可见的原始观战比分板。更换游戏分辨率、观战 HUD 缩放、窗口模式或布局后，重新核对区域。

向直播姬发送节目时，继续使用已有的 [Bilibili 第三方模式流程](Bilibili直播姬.md)。OCR 和 Replay 接入不会配置平台服务器、开播或改变 OBS 的设备来源。
