# 实时预览、个人经济与静默启动

2026 年 10 月 4 日的这次更新包含三项：读取原生观战计分板的个人累计金币，工作台显示连续 OBS 合成画面，常规桌面启动隐藏准备终端。

## 个人经济、KDA 与补刀

原生观战金币列 `123(9423)` 显示当前余额 123 和累计金币 9423。系统保存两个独立值，累计金币进入个人经济排名、选手焦点和比赛记录；当前余额在实时数据表单独展示。

客户端实际返回有效 `totalGold` 时优先采用该字段。缺失时使用 Windows OCR 读取底部计分板，按同侧英雄头像确认当前对局中的选手身份。每行识别括号外余额、括号内累计金币、K/D/A 及补刀，将同一画面的统计一起更新到双方阵容、实时数据、节目和当前对局快照。计分板中的 KDA 与补刀可以纠正 API 中尚未同步到当前回放画面的统计；API 继续提供选手名称、英雄、等级、装备和符文。

金币列、KDA 列及补刀列采用各自的几何位置，避免混入头像旁的死亡数字或悬赏金额。可靠的英雄匹配与完整的数字行共同决定采样是否可用；缺少字段、头像无法确认、重复身份、截断数字及数字歧义会等待下一次有效采样。

启用团队观战 OCR 后，个人识别自动跟随开启；也可单独开启或关闭个人识别。进入“连接与输出”或“实时数据”的“团队与个人经济来源”，显示原生底部计分板的金币列，按需要调整识别区域并保存。默认个人区域覆盖游戏客户区完整宽度、高度的 40%–100%，保留两侧金币列、中央头像以及全部五行。旧默认区域只覆盖宽度的 25%–75%、高度的 65%–100%，容易漏掉两侧金币和上方选手。

内置 OBS 已连接时优先读取原始游戏捕获的 PNG，游戏窗口处于后台或被其他桌面窗口遮挡时仍可采样。原始捕获包含游戏计分板，采集区域按捕获画面的完整尺寸计算。外部 OBS 或原始游戏捕获不可用时回退 Windows 屏幕采样，回退期间游戏窗口需保持可见且采样区域无遮挡；另一块屏幕上的可见窗口可以持续采集。两条路径都要求原生计分板已在游戏画面中展开。装备视图独立提供 KDA 与补刀，个人经济需要画面显示金币列。

每个个人金币和 KDA / 补刀读数分别保留来源、采样时间及对应游戏秒数。统计有效期为 3 秒，金币有效期为 10 秒；金币 OCR 过期显示 `—`，KDA 与补刀回退到当前局内 API 统计。切局、换队、切换数据模式及明显回放跳转会清除旧样本；局内 API 断开、阵容采样过期或回放跳转后尚未取得对应 Live 样本时暂停个人识别。工作台及实时数据表标记 `OCR` / `API`，悬停统计数据可查看来源和采样时间。经济来源面板分别显示统计与金币的匹配人数、采样时间及本次耗时，“3 秒后读取一次”提供可核对的单次识别反馈。战队名称与简称保留赛事设置，并明确标注“赛事资料”。自动 HUD 模式在个人 OCR 开启时保留原生底部计分板，离开局内节目或关闭软件时沿用原有恢复逻辑。

识别采用常驻 Windows OCR 进程，重复使用语言引擎与官方英雄头像模板；缓存仅保留识别区域，每帧重新核验头像和数字。底部计分板按数字列提取小块，提高小数字识别率；补刀单元漏读时使用同帧已确认字形校验，歧义读数等待下一帧。正常向前播放时，下降的 KDA / 补刀和累计金币不会刷新有效期。识别调度独立于局内 API 轮询，以 500 毫秒间隔发起，前一帧未完成时串行等待。内置 OBS 的 PNG 使用较低压缩成本，保留原始分辨率与无损像素。预热在捕图前完成，读数有效期从取图时刻开始。装备视图更新统计时保留先前金币的原始采样时间，经济曲线继续使用金币实际采样的游戏秒数。

## 比赛时间连续显示

顶部比分板、工作台和选手详情使用统一显示时钟。局内 API 与 Replay API 提供真实时间锚点，客户端用单调时钟在轮询间连续推进，并逐渐校正小幅采样误差。Replay 的暂停和倍速直接控制推进，拖动回放或更换对局会重新定位；接口样本过期或导播 WebSocket 断开时冻结。比赛记录、事件和十分钟卡片继续使用 API 实际采样时间。回放跳转后，保存记录等待当前位置对应的 Live 数据，防止把跳转前统计写进新位置。

局内 API 未提供完整有效的选手统计时，KDA 与补刀显示 `—` 并标注“未提供”，待完整计分板采样后更新。有成员缺少有效统计的队伍，其击杀合计也显示 `—`，避免把缺失数据呈现为真实的零击杀。

真实比赛记录要求有效的游戏采样，导出保留个人统计和金币各自的来源、采样时间及对应游戏秒数。保存时拒绝缺失或过期的统计，清除过期金币，并排除当前回放时间之后的事件。十分钟卡片仅采纳 600–605 秒窗口内的对应读数；当前真实阵容按选手 ID、阵营与英雄隔离，上一场不同阵容的卡片保留在历史中。无法从原生面板取得的击杀、小兵等分类收入继续显示“未提供”。

## 已查接口及适用范围

| 接口 | 官方公开数据与本次用途 |
| --- | --- |
| `/liveclientdata/activeplayer` | `currentGold` 为当前玩家可花费余额，不能直接作为十名玩家的累计金币。 |
| `/liveclientdata/playerlist`、`/playerscores` | 官方示例提供名单、装备、KDA、补刀等；没有列出每名玩家的 `totalGold`。`allgamedata` 中的列表字段名为 `allPlayers`，本机版本的额外字段仍按实际响应处理。 |
| `/liveclientdata/allgamedata` | 已有适配器持续获取名单、英雄及比赛时间，为同侧英雄头像匹配提供当前对局身份。 |
| `/swagger/v3/openapi.json` | 游戏运行时用于核对该客户端实际提供的字段；早期接口核查时游戏进程未运行。本次计分板修复另外读取了正在运行的 `allgamedata` 和 OBS 原始游戏捕获。 |
| Replay API | 用于回放镜头、播放、渲染开关及制作控制。 |
| Spectator-v5 | 当前比赛及阵容定义未列个人金币字段。 |
| Match-v5 Timeline | `ParticipantFrame` 定义确实提供 `currentGold` 和 `totalGold`，适用于 matchId 对应的时间线；公开说明未承诺局内每秒更新。 |

依据：[Riot Game Client / Live Client Data 官方说明](https://developer.riotgames.com/docs/lol#game-client-api)、[Riot League Director](https://github.com/RiotGames/leaguedirector)。详细端点、官方字段及使用边界见 [Riot 经济接口核查](riot-economy-apis.md)。公开示例的缺项无法证明所有版本与受限赛事接口都缺少该能力，本次保留有效原生字段的优先级。

## 节目原生显示与低频预监

Electron 桌面内置模式中，工作台最大的节目播出区域嵌入 OBS 原生投影窗口，按 OBS 的 30 / 60 FPS 配置显示合成画面。该路径去掉逐帧截图、JPEG 编码、传输及浏览器解码，画面位置和尺寸随页面布局、滚动和缩放更新。界面标注“原生显示”；旁边的 FPS 来自 OBS 合成统计，屏幕实际呈现率需要独立的 Windows 帧事件验证。工作台预监及“连接与输出”中的合成核对使用每秒 1 帧快照，完整操作见 [单屏导播与制作流程](导播工作流.md)。

内置 OBS 使用 `RiftCast 节目` 与 `RiftCast 预监` 两个场景。预监共享游戏捕获并采用独立 `?preview=1` HUD；工作室预监总线保持该场景活跃，以便浏览器来源持续渲染。外部模式只读取已有节目和工作室预监，需外部 OBS 已开启工作室模式。

原生投影只关联当前应用拥有的内置 OBS 进程及对应节目窗口。隐藏页面、离开监视器所在页面、手动暂停或关闭桌面时释放投影，恢复后重新创建，防止窗口残留或遮挡其他页面。预监与设置页均不创建原生投影。

浏览器运行和外部 OBS 模式保留本机 `/ws/obs-preview?kind=preview|program` 兼容订阅，接收 960 × 540 JPEG，界面标注每秒 1 帧合成快照。服务端统一将所有截图订阅限制为每秒 1 帧，涵盖预监、设置页及兼容节目路径。同一总线共享采集，新订阅按该总线采样节奏获得画面，两路像素读取串行执行，客户端解码后发送 `next`，避免慢客户端积压。隐藏、暂停或离开页面时取消订阅，恢复及断线时重新连接。预览控制接口只允许导播主机访问。

依据：[OBS WebSocket 官方协议](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md)。低频 `/api/obs/engine/preview` 保留用于诊断。原生显示路径及测量方法见 [原生预览性能](原生预览性能.md)。

## 静默启动

双击 `启动导播.vbs` 全程隐藏准备终端，原有 CMD 入口调度后立即退出。依赖准备结束后直接打开 Electron 并退出 PowerShell。准备日志保存在 `%LOCALAPPDATA%\RiftCast\logs\launcher.log`，失败通过弹窗显示原因及日志路径；日志及弹窗经过凭证脱敏。桌面运行日志在“帮助 → 打开启动日志”。`-Console` 保留诊断终端，`-Browser` 保留控制台便于 Ctrl+C 停止服务。

## 当前检查与边界

本版包含 OCR 字词与玩家身份匹配的回归样本，以及有效期、累计金币、缺失统计、回放跳转和比赛时钟的服务测试。界面验收使用独立演示数据，当前检查结果见 [验收说明](验收.md)。

真实观战布局中的持续 OCR、游戏运动、摄像头和平台输出需在目标设备核对。历史原图、性能数据与过程记录已移出源码项目；测试样本保留来源与适用边界。
