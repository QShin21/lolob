## 四项问题怎样修复

| 验收问题 | 本轮实现 | 仍须独立验证 |
| --- | --- | --- |
| P1：保存人工 BP，不 TAKE 就改变 PGM 英雄 | 人工接管前保留当时正在播出的自动 BP；待播继续使用独立的 draft，最后 TAKE 的快照不被保存动作改写。同场景再次 TAKE 才发布人工内容 | 真实 HTTP 和 /overlay 显示；延迟成功与失败、重复请求、客户端 BP 连续变化 |
| P2：重启后旧席位仍可提交 | 每次 WebSocket 重连都清除前端有效授权，再通过只读 GET /api/control/seat 验证。失效席位返回明确错误，不重新签发其他角色；按钮与快捷键在验证前禁止写入 | 五角色重连、旧请求迟到、真实 LAN 令牌更新、邀请恢复后的权限 |
| P2：长错误遮住底部 TAKE | 通知与播控条放在同一安全区域，通知锚定在播控条实际高度的上方。移除旧的固定 bottom 定位；长通知内部滚动，完整错误文字保留 | 1366×736 等有效高度、双主题、鼠标中心及四角命中、长内容与小屏 |
| P3：非空英雄搜索首次 Escape 只清空 | 弹窗阻止 search 输入的默认清空，直接关闭并返回原槽位。输入法合成时不抢 Escape，提交中不允许取消 | 非空/空搜索、焦点返回、输入法、弹层内无误 TAKE |

BP 的例子：上次 TAKE 是 Aatrox，合法自动样本已经走到 Gwen；此时手工保存 Akali，节目继续显示 **Gwen**，不会退回旧的 Aatrox，也不会提前显示 Akali。再次明确 TAKE 才显示 Akali。

新增 `production.programDraftHold` 保存人工接管前的可见 BP，与最后 TAKE 的配置分开。接管、差异核对、清空、回退都先建立保留值，后续保存不会覆盖它。恢复客户端自动同步只更新待播，须 TAKE 后才重新跟随自动样本。正常连续自动 BP、同局时间与统计采样保持原有更新路径。

同场景 TAKE 成功发布时清除保留值；准备期间或 OBS 应用失败不提前清除。撤回上次切换同时恢复当时的可见 BP。新字段随原状态文件保存；旧状态没有该字段且已处于人工模式时，回退到已接受的节目快照，绝不读取人工待播。原 revision、requestId、CAS 和“已接收 / OBS 已应用 / 人工已核对”区别均保留。

席位恢复区分两份数据：服务器刚验证的身份才允许提交；上次验证过的显示身份只让已打开的任务继续挂载，保留本地输入。桌面验证期间暂停主工作区交互，播控与快捷键也检查有效身份。移动端旧任务保留且禁写，不把旧字幕席当成已授权的新资料席。

主机有“重新连接主机导播席”按钮，明确建立新身份；已有其他控制者时仍须原有显式接管。移动端可以在当前页粘贴主机重新发出的完整邀请，验证同工作站身份后再替换席位与配对令牌，不刷新页面、不自动 TAKE。过期邀请不会因重新载入页面而自动获得新角色。跨工作站迁移、真实 LAN 重配对和手机系统体验仍需后续测试。

## 给 Sol 的启动命令

先核对本轮最终提交和 origin/new 一致，工作区源码干净；最终 SHA 以本交接后的推送结果为准。依次执行：

```bash
cd /workspace/lolob
git rev-parse HEAD
npm run build
RIFTCAST_OFFLINE=1 RIFTCAST_AUTO_CONNECT=0 RIFTCAST_OBS_AUTOSTART=0 npm test
RIFTCAST_EXPECT_SOURCE="$(git rev-parse HEAD)" npm run verify:frontend-safety
```

本环境若使用平台预装的 Playwright 和 Chromium：

```bash
RIFTCAST_PLAYWRIGHT_MODULE=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs \
RIFTCAST_CHROMIUM_PATH=/usr/bin/chromium \
RIFTCAST_EXPECT_SOURCE="$(git rev-parse HEAD)" npm run verify:frontend-safety
```

脚本锁定指定源码 SHA，拒绝带有未提交实现的验收运行。Playwright/浏览器在其他环境的路径按实际安装选择，不要求该 Linux 路径在 Windows 存在。

手动检查也只能使用新建隔离目录：

```bash
qa_dir="$(mktemp -d /tmp/riftcast-safety-sol-XXXXXX)"
RIFTCAST_DATA_DIR="$qa_dir" PORT=3899 ENABLE_LAN=0 RIFTCAST_AUTO_CONNECT=0 RIFTCAST_OBS_AUTOSTART=0 RIFTCAST_OFFLINE=1 RIFTCAST_OBS_MODE=external npm start
```

访问 `http://127.0.0.1:3899`。不使用真实 data/runtime、录制或 OBS 恢复目录。设备桩不能证明实际音画送出；本轮不操作真实 OBS、直播平台、驱动安装/卸载、UAC 或系统重启。不发布、不推 main，不覆盖旧版本或标签。
