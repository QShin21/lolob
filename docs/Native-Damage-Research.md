## 版本与来源

- 游戏构建：`16.20.824.8524`
- 原始 EXE SHA-256：`EE3C887B4579AEAB12CA77B2A43CC1CC3411A8AA30BC43D2DFEA856F6CE497C8`
- 观战读取器先校验精确构建和文件哈希，协议解析仅启用对应配置。
- 解码器研究使用 [rofl-parser](https://github.com/shyunku-libraries/rofl-parser)，提交 `73530424162672aa7daafe233f647cc655607880`，包版本 26.16.1，声明 ISC。许可证及变更说明见 `THIRD_PARTY_REPLAY.md`。
- 生产依赖：`fzstd@0.1.1` 解压 ROFL2，`egoroof-blowfish@4.0.3` 解码观战分片；gzip 使用 Node 标准库。

## 数据路径

真实观战读取当前游戏进程的观战服务器、比赛标识、目标和短期观战凭据，仅在采样器与服务的私有 IPC 内传递。连接使用与游戏相同的服务器；凭据不进入节目状态、存档、日志或导出。

旧路由 `getLastChunkInfo` 与 `getGameMetaData` 提供分片索引及本场解码参数。当前分片使用 `/rest/spectator-consumer/shards/{platform}/players/{target}/game/chunks/{id}`，携带 `X-Riot-Spectator-Key`。数据经过 Blowfish ECB / PKCS5 和 gzip 还原，再解析时间戳与伤害事件。

观战服务器现场仅保留近期约六个分片。首次抓取最近五片，后续连续追加，记录采集起点；不把部分时段总和标记成全场伤害。播放暂停和倒退按游戏时间查询，尚未播放的事件不进入节目。过期历史形成缺口时切换采集会话，已有团战段失效，重新切入后建立新基线。

ROFL2 从当前回放文件解析全部游戏分片，快照分片只用于核对十名英雄的网络标识。累计结果须通过全部十名英雄的官方赛后数据校验才开放；播放时只查询当前时刻。未知格式、异常大小、重复片、截断或总量不一致均停止输出。

英雄关联使用网络标识、英雄和阵营三项交叉检查。伤害事件只统计敌方英雄目标，保留物理、魔法、真实伤害分项。宠物等独立对象的归属需要额外覆盖验证；ROFL 全场校验能够拒绝归属缺失的样本，现场验证范围仍限已观测阵容。

## 构建研究记录

原始可执行文件保持不变。离线内存镜像复制为 PE 研究文件后，适配工厂入口：

| 项目 | RVA / 标识 |
| --- | --- |
| 包工厂 | `0xe6c770`，长度 `0x10a60` |
| 工厂范围检查 | `0xe6c7a0`，字节 `81 fb e9 04 00 00` |
| 跳转表 / 最大 ID | `0xe7d1c8` / 1257 |
| UnitApplyDamage | 包 ID 359，处理函数 `0x2d0be0` |
| 构造 / 反序列化 | `0xe3d7b0` / `0xeb9180` |
| 解码字段 | 参数 1 目标、8 来源、9 float 金额、2 类型 |

在上述固定上游提交的工厂发现器中按签名字节返回相应工厂范围与跳转表，再运行：

```text
node src/cli/interpret.js --input module-research.pe --patch 16.20 --binary-version 16.20.824.8524 --output cn-decoder/packets.json
```

从输出保留包 359 的解码函数，去重查找表，添加完整消费、长度和整数边界检查，生成 `server/protocol/cn-16.20-damage.ts`。三个实际包样本存于 `server/fixtures/cn-damage-16.20.json`，分别验证三种伤害类型。包头 param 有时指向代理对象，应以解码字段确认伤害来源与目标。

早期检查的统计树 RVA `0x1ee9418` 及伤害计数字段在回放和真实观战中均存在停滞，尽管生命值和战斗事件变化。该累计内存路径没有作为生产伤害来源。
