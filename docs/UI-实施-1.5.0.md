# RiftCast 1.5.0 操作界面实施记录

本次按 [UI 改版方案](UI-改版方案-1.5.0.md) 完成操作界面重排与主题收口。初审条目见 [UI 审查记录](UI-审查-1.5.0.md)。

| 范围 | 最终行为 |
| --- | --- |
| 导播台 | 紧凑引导入口，监看、下一次切入、场景库形成连续工作区；1366×768 与 1366×736 保留两行完整场景。 |
| BP | 总览、最终归属、接管与客户端差异、规则与历史四个工作区前置；各编辑器保持挂载。 |
| 设置 | 15 项任务按四组组织，支持搜索与方向键、Home、End；筛选后首个结果可通过 Tab 进入。 |
| 节目包装 | 拆分六个子任务；身份/品牌与局内分析使用共享保存条，其余组件保留各自保存动作和作用范围提示。 |
| 声音 | 首屏直接显示混音推子、节目总线与音乐；采集设备按需展开。 |
| 赛事与素材 | 队伍摘要显示名单和账号完整度，名单独立滚动；整届赛事表单具有固定摘要与提交区。 |
| 空状态与帮助 | 空数据连接和图片导入提供就近入口；帮助文章顶部显示下一步操作，目录与正文分别滚动。 |
| 手机遥控 | 五种席位保留原权限，编辑席先显示任务；监看单独切换，字幕草稿 DOM 保持；主导播 TAKE 固定。 |
| 视觉 | 深浅主题统一表面、边框、文字、焦点环和状态语义；桌面图标热区至少 32px，手机按钮和折叠项至少 44px。 |

`src/design-tokens.css` 提供共享视觉变量。`src/operator-150.css` 位于操作样式末层，选择器限制在工作台、远程控制和编辑器；媒体画布、演示图形和观众输出保留各自样式。保留原有任务 ID、可复用 aria-label、业务命令、席位权限与 TAKE 语义。

`useConfigDraft` 新增 `localPatch`，按当前草稿相对其基线计算本地修改字段。基础包装保存继续提交 `expectedConfigVersion`；外部更新触发原有冲突核对，保留本地修改后仅写入相关字段。独立选手画面和倒计时的保存结果不会被共享草稿覆盖。`changedFields` 继续用于说明外部变化。

验收命令：

```text
npm run check
npm run build
npm run verify:operator-ui
```

新增脚本 `scripts/verify-operator-ui-150.mjs` 启动临时数据目录和独立端口，关闭游戏自动连接、OBS 自启及外部资源访问，并在结束后关闭进程与清理临时数据。输入包括八支队伍、十人手工 BP、二十张本地素材和长赛事名；空状态采用明确的只读响应样本。

最终报告位于 `verification-output/operator-ui-1.5.0/report.json`，包含 `version: "1.5.0"`、`status: "passed"`、14 组检查、112 张截图、尺寸与对比度记录，以及每项检查对应的截图文件。检查涵盖：

- 1366×768、1366×736、1440×900、1920×1080、1080×768 的导播布局；390px 与 430px 的五种手机席位。
- 两主题下全部设置任务、包装子任务、BP 工作区、赛事子任务、数据、收尾、帮助和主要对话框。
- 设置搜索后的 Tab / Enter、Home / End；BP 弹窗 Escape 焦点恢复；第五名选手滚动完整可见。
- 实际编辑保存战队、建立八队赛事、独立包装保存和冲突处理；最终品牌 patch 只包含 sponsor，PGM 保持原快照。
- 字幕任务与监看切换后保留同一个输入节点；受限席位没有 TAKE；当前主导播控制条保持可见。
- 资源、VDO 权限反馈、诊断、图形演示、观众互动与工具按钮文字对比度均达到 4.5:1，样本最低为 5.87:1。

报告记录零浏览器运行时错误、零意外 TAKE。UI 自动化覆盖浏览器与隔离服务；真实 OBS 合成、游戏、物理音视频设备和平台播出由对应验收流程确认。
