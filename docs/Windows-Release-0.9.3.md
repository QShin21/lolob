# RiftCast 0.9.3 Windows x64

本版从 0.9.2 升级赛后报告的数据链路。左侧显示十名英雄的累计经济，右侧资源仅显示防御塔、小龙、大龙和虚空巢虫，删除远古龙与峡谷先锋。全部使用本局过程中保存的 OCR 观测值，经济曲线同样保存 OCR 采样。KDA 沿用已有选手统计。

## 采集与校准

在「连接与输出」的「经济与顶部资源 OCR」中启用所需采集。顶部资源可以独立开关，个人经济和团队经济维持各自设置。升级后，已开启团队 OCR 的配置默认同时采集顶部资源；可用校准下拉框逐项调整双方的四种资源数字框。

默认资源坐标按本次提供的原生顶部 HUD 设置，随游戏捕获图像宽高归一化缩放。蓝方从左到右为小龙、大龙、虚空巢虫、防御塔，红方从左到右为防御塔、虚空巢虫、大龙、小龙。数字框应只覆盖计数，避开旁边图标和金币。游戏 HUD 缩放、宽高比或布局有变化时需重新核对校准；截图文字、图标或包装遮挡会造成缺采。

个人经济需要显示观战计分板的累计金币列，并确保英雄行可见。装备、补刀、悬赏和当前持有金币均不转换成累计经济。示例截图中的计分板处于补刀列，单靠该截图无法取得十名英雄的累计金币；顶部团队经济与资源仍可读取。采集界面会显示个人经济及八个资源单元格的状态。

资源新增或变化须经连续两帧一致确认，真实的 0 会正常保存，缺失和疑似文字不会当作 0。每个单元格独立更新，局内缺采或过期不会抹掉已保存的有效读数。计数倒退会被拒绝；回放跳转、重开、下一局、交换双方以及来源对局变化会清除当前采集上下文，避免串局。当前尚未完赛的留存记录会随赛事数据保存并在重启后按对局标识恢复。

## 赛后报告

比赛结束后，导播在「本局资料」确认本局赛果，报告使用该局冻结的数据快照。第一页展示英雄经济、KDA、团队经济、四类资源、禁用英雄和经济曲线。第二页保留 0.9.2 的英雄对位布局；缺少伤害与承伤数据时不补造占比。

已采集的英雄金币和资源即使超过局内实时有效期，赛后仍可使用。报告明确标注「OCR 最后有效样本」，没有读到的数据标记为「未采集」。这些金额和计数代表最后一次有效观测，不保证等于未被捕获的最终帧。经济曲线保留每五秒区间内的最后一个真实样本，不为缺采时段编造数值。

确认后，在场景库选中「赛后报告」，先核对 PVW，再 TAKE 播出。载入下一局不会改动已播出的上一局报告或历史记录。旧版本的报告没有 OCR 留存时，缺失资源会显示「未采集」。

## 安装与构建

安装版为 `RiftCast-0.9.3-Setup-x64.exe`；免安装版为 `RiftCast-0.9.3-Windows-x64.zip`，须完整解压后运行 `RiftCast.exe`。默认资料目录沿用 `%APPDATA%\RiftCast`。升级前退出程序并备份已有资料。包内包含独立 OBS、相关第三方许可与对应源码；不附带操作者账号、推流凭据或比赛资料。

构建命令：`npm ci`、`node scripts/ensure-vbcable.cjs`、`npm run check`、`node --import tsx --test --test-concurrency=1 server/*.test.ts`、`npm run build`、`npm run release:win`。正式包须在 Windows x64 构建。Release 同时提供 `release-manifest.json` 与 `SHA256SUMS.txt`，记录源码提交及产物校验值。

## 验证边界

新增自动化覆盖数字解析、蓝红布局、零值、两帧确认、独立缺采、过期留存、长局经济曲线、冻结、重启、历史报告、下一局及回放跳转。Windows 测试用本次截图提取的数字字形像素（背景与队伍颜色归一化）运行正式 OCR worker，覆盖八个资源数字与双方团队经济。字形像素测试验证所给字体与布局，无法替代目标机器的实际游戏捕获、不同 HUD 缩放和长期采集验收。

真实 LoL 对局、驱动安装与 UAC、升级/卸载数据隔离、真实平台推流和观众端音画效果仍需在目标设备验证。自动化测试与构建结果以对应 GitHub Actions 记录为准。
