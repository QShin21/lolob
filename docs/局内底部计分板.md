# 局内底部计分板

局内场景底部使用用户提供的转播参考图布局：左下角版本块、蓝方选手画面、中央五行计分板、红方选手画面。左下角英雄属性面板和右下角小地图由游戏提供，RiftCast 在这两个区域保持透明，自动 HUD 处理保留对应开关。

中央计分板使用纯黑背景，opacity 为 1，透明度为 0。每行包括双方英雄与等级、召唤师技能、符文、装备槽、饰品、K/D/A、补刀及可用状态；中央显示同位置选手的累计经济领先。装备空位保留，数据缺失显示空槽或“—”。选手按上单、打野、中单、下路、辅助对齐。字段与归档流程见 [当前 HUD 与赛后归档](当前HUD与赛后归档.md)。

## 设置图片、摄像头和版本

打开“连接与输出 → 局内底部包装”：

1. 修改游戏版本和计分板标题。
2. 为双方独立选择图片、摄像头或关闭画面。图片可直接上传，也可选择已上传素材；支持 PNG、JPEG、WebP、GIF，单张最大 8 MB。
3. 摄像头列表由当前 OBS 引擎读取。先连接内置引擎或外部 OBS，再刷新列表并选择设备。
4. 上单、打野、中单、下路、辅助五组对位各自配置蓝、红双方的摄像头或图片。图片留空时自动使用赛事阵容中的定妆照，姓名留空时使用对应位置的选手名。
5. 工作台的「选手画面切换」中点击位置即可手动切入并固定；点击「5 秒自动轮播」后按五路顺序每 5 秒切换一组。手动选择位置或点击「停止轮播」会立即停止自动切换。轮播使用服务端墙钟，比赛暂停期间继续；预监和节目均离开局内场景时暂停，重新进入后完整显示当前组 5 秒。
6. 旧版两侧画面自动迁移到打野组；原有摄像头、图片及名称保留。所有组的素材设置与当前手动/轮播模式都会保存。
7. 保存设置后先核对预监，再切入节目。

图片在浏览器 HUD 中显示。摄像头由 OBS 视频采集来源显示，置于浏览器姓名条下方，按窗口裁切填满；预监和节目分别随场景启用。摄像头音频保持静音。浏览器画面链接单独打开时，摄像头像素需在 OBS 合成预览中查看。

## OCR 经济差

底部中央五行经济差使用个人累计金币 OCR，沿用“团队经济来源与校准”中的个人计分板识别区域。原生游戏计分板需显示金币列 `当前金币(累计金币)`，软件用同侧 KDA 和补刀的唯一匹配确认选手，再相减双方累计金币。OCR 读取游戏窗口，OBS 包装保持在合成输出中。

实时模式只接受带有效期的 OCR 个人累计金币，10 秒后失效，样本缺失或无法唯一匹配时对应行显示“—”。当前可花费金币和装备总价均不参与这五行经济差。演示模式使用明确标记的演示数据。

## 验证范围

当前隔离 HUD 检查由 scripts/verify-lpl-hud.mjs 完成，覆盖五行布局、不透明背景、镜像列序、图片解码及缺失状态。服务测试覆盖分路映射、经济来源与配置校验；OBS 测试覆盖摄像头来源和预监/节目请求。完整检查结果见 [验收说明](验收.md)。

[当前局内 HUD 预览](screenshots/current-live-hud.png) 使用明确的演示数据。物理摄像头、游戏画面遮挡和实际直播输出需在目标设备验收。
