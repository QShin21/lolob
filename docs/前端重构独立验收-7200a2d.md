## 需要 Astra 修复的边界

### P2：同一事件回合重复保存产生两条记录

管理 → 比赛记录，填写记录标题，模拟一次提交失败以核对输入保留，再恢复真实隔离服务。将响应延迟 500ms，在同一 JavaScript 事件回合调用“保存记录”按钮的两次原生 `click()`：实际发送 **2 个 `save-recording` 请求**，服务端保存 **2 条同名快照**。两个请求使用各自的新 requestId，服务端正常将它们视为不同请求。

原失败断言仍在 [独立脚本](evidence/sol-7200a2d/workspaces-browser.mjs) 中，结果见 [67 项结果](evidence/sol-7200a2d/workspaces/results.json)、[重复请求与记录数](evidence/sol-7200a2d/workspaces/duplicate-recording-observation.json)、[失败截图](evidence/sol-7200a2d/workspaces/failure-records-failure-input-and-double-submit.png)。

具体范围必须说准确：额外使用 Playwright 的真实鼠标 `dblclick`，只发送 1 个请求并生成 1 条记录，见 [鼠标双击](evidence/sol-7200a2d/workspaces/pointer-double-click-observation.json)。本轮复现的是同步重入边界，不能宣称普通鼠标双击必然重复，也没有观察到比分重复累计或 PGM 提前变化。

静态原因：[ManagementRecords.tsx](../src/pages/ManagementRecords.tsx) 的 `save()` 只读取 React `busy` 状态；同一回合的第二次回调仍可能读取旧值。管理主表单与收尾动作另有同步 ref 门禁，本轮相同触发方式只发一次。交 Astra 补齐记录保存的同步门禁，并保持请求超时/不确定结果的幂等核对；仅禁用按钮不能说明全部重试语义已解决。
