### 数据

- 十人、分队、对位和个人详情共用当前或冻结的实际数据；累计经济、当前金币、装备价值分开；缺失保留 `—`，来源、采样与有效期分别显示。
- 经济图沿用原样本/缺口/交互实现；事件单列；原经济来源和 OCR 校准仍在“来源与校准”。查看冻结终局时不操作当前校准。
- 装备目录或图片不可用时明确提示，不补假图片；装备明细是可选列，个人检查保留装备与符文。CSV/JSON 导出对应当前正在查看的对局快照。
- 数据页访问后保持挂载，保留筛选和校准工作状态；没有增加页面载入自动写入。

### 管理与素材

- 赛程全部原字段、载入比赛说明、战队稳定 ID、选手稳定 ID、账号匹配、照片和队标继续使用原契约。新对象生成新 ID，编辑不会重建已有选手身份。
- 草稿按对象保存。提交使用 `expectedConfigVersion`；冲突保留输入并展示本地/服务器差异，用户明确核对后再采用新版本。保存、载入比赛与 TAKE 保持分开。
- 载入比赛、删除约束和主控制者判断继续受服务端裁决。普通资料席可编辑允许的资料，不因此获得载入或播出权。
- 素材为列表与检查区；展示尺寸、透明原图、人物竖幅裁切预览、待播和节目引用；上传仍为 PNG/JPEG/WebP/GIF、8MB、实际 XHR 进度和失败反馈。失败后的重试提醒先核对已经收到的文件。没有增加服务端不存在的删除能力。
- 记录包含原保存记录与有效终局快照，避免短历史列表截断后无法访问归档；本局录像只按真实标识关联。报告排版预览不写 PVW。英雄图库继续使用现有授权资源。

### 帮助与收尾

- 帮助覆盖准备、BP、数据/OCR、预监、TAKE、伴侣、音乐、冲突、席位、恢复、收尾、启动。快捷键来自实际配置；版本来自 package；运行环境只显示已知事实，不把浏览器识别当作安装版/便携版识别。
- 实际目录未由现有接口提供时直接说明，未伪造用户路径。桌面日志使用现有 IPC 并保留错误反馈。
- 收尾保留 `finalize-game`、`accept-final`、`correct-result`、`remake`、`next-game`、`save-recording`；输入理由按本局键保留，防止重复点击。
- “节目报告已核对”必须是本局、本版、postgame 且 `checkValid(program)`。下一局仍按实际胜方、终局、系列赛完成和控制权阻塞，没有凭界面勾选跳过状态保护。
- 输出区各自读取 RTMP、虚拟摄像头、节目音频桥、录制状态，各自保留停止按钮。仅主机当前主导播可操作；部分停止失败或音频仍受托管时不显示全部结束。未新增任何自动启动或安装动作。

手动隔离启动（端口占用时自行选空闲 loopback 端口）：

```bash
cd /workspace/lolob
npm run build
qa_dir="$(mktemp -d /tmp/riftcast-four-workspaces-sol-XXXXXX)"
RIFTCAST_DATA_DIR="$qa_dir" PORT=3899 ENABLE_LAN=0 RIFTCAST_AUTO_CONNECT=0 RIFTCAST_OBS_AUTOSTART=0 RIFTCAST_OFFLINE=1 RIFTCAST_OBS_MODE=external npm start
```

访问 `http://127.0.0.1:3899`。可用测试工具环境：

```bash
export RIFTCAST_PLAYWRIGHT_MODULE=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs
export RIFTCAST_CHROMIUM_PATH=/usr/bin/chromium
export RIFTCAST_EXPECT_SOURCE="$(git rev-parse HEAD)"
```

先读待运行脚本，确认隔离目录、来源身份和引擎动作保护，再执行完整测试。Astra 的短自审可用 `node docs/evidence/astra-workspaces/visual-check.mjs` 复跑，但它会重写自己的证据；Sol 应使用独立证据目录并形成自己的结论。
